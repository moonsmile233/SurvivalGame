## 1. 原始需求

```text
2D 生存挑战游戏（Unity WebGL + H5 页面）

【Unity 部分】
- 创建一个 2D 游戏场景；
- 玩家可以移动；
- 敌人定时生成并追踪玩家；
- 玩家有生命值，受到攻击会掉血；
- 生存 60 秒获得胜利；
- 支持失败、重新开始、暂停；
- 显示分数和剩余时间；
- 使用 Unity 构建 WebGL 版本。

【H5 部分】
- 制作一个简单的 H5 外壳页面：
  - 输入玩家昵称；
  - 开始游戏按钮；
  - 嵌入 Unity WebGL 游戏；
  - 游戏结束后，Unity 把分数传给 H5；
  - H5 显示本次成绩和历史最高分；
  - 最高分使用 localStorage 保存；
  - 页面适配电脑和手机宽度。

【必须完成】
- 游戏能正常开始、结束和重开；
- Unity WebGL 能在浏览器运行；
- H5 和 Unity 能互相传递数据；
- 刷新页面后最高分仍然存在；
- 提供源码、WebGL 构建文件和 README。
```

## 2. 这个项目真正的难点

先认清工程量分布，规范才有意义：

| 模块 | 易被低估的点 | 建议投入 |
|---|---|---|
| Unity 玩法 | 其实最简单，2 小时能出核心 | 25% |
| WebGL 构建 | 体积、压缩、托管、加载失败 | 25% |
| H5 ↔ Unity 桥接 | 加载时序、消息只发一次、移动端传参 | 25% |
| 外壳页面与适配 | 横竖屏、iOS Safari、安全区 | 15% |
| 文档与验收 | 让别人能跑起来 | 10% |

**核心判断：这个项目的风险不在"写游戏"，而在"让游戏在浏览器里可靠地跑起来、并且和页面说上话"。**

因此规范的第一条原则：

> **先打通最薄的一条垂直链路（空 Unity 场景 → WebGL → 自定义 H5 页面加载 → 双向传一条消息），再往里填玩法。**

不要先做 10 小时玩法，最后发现 WebGL 构建失败或桥接调不通。

## 3. 技术选型与版本锁定

| 项 | 选择 | 说明 |
|---|---|---|
| Unity | **Unity 6 LTS（6000.x）**；保守可选 **2022.3 LTS** | 二选一，写进 README 并锁定到具体小版本 |
| 渲染管线 | **Built-in Render Pipeline** | 2D 小游戏不需要 URP，包体更小、配置更少 |
| 脚本后端 | **IL2CPP**（WebGL 默认，不可选 Mono） | 必须 |
| 目标平台 | **WebGL 2.0** | Unity 6 已不支持 WebGL 1；iOS 需 15+ |
| C# 版本 | 跟随 Unity 默认 | 不用 Unity 不支持的语法 |
| H5 | **原生 HTML + CSS + ES Module JS，零构建、零框架** | 一个人的项目，不引 Node 工具链；任何静态服务器可直接跑 |
| 本地服务 | `python -m http.server` 或 `npx serve` | README 里给两条命令 |
| 浏览器 | Chrome / Edge / Safari 15+ / iOS Safari / Android Chrome | 见验收矩阵 |

**版本纪律：**

- Unity 版本号必须写进 `README.md` 和 `ProjectSettings/ProjectVersion.txt`，且两者一致。
- H5 侧维护 `APP_VERSION` 常量，页脚显示；`docs/` 记录"H5 版本 ↔ WebGL 构建版本"对应关系。
- 不升级 Unity 大版本，除非有明确理由并重跑全量验收。

## 5. Unity 侧架构规范

### 5.1 单场景 + 显式状态机

只有一个场景 `scn_Game`，由 `GameManager` 持有状态：

```csharp
public enum GameState
{
    Booting,   // 初始化中
    Ready,     // 等待 H5 发来 Start
    Playing,
    Paused,
    Won,
    Lost
}
```

**状态迁移表（唯一合法路径）：**

| 当前 | 事件 | 目标 |
|---|---|---|
| Booting | 初始化完成 | Ready |
| Ready | `StartGame` | Playing |
| Playing | `PauseGame` / 失焦 | Paused |
| Paused | `ResumeGame` | Playing |
| Playing | HP ≤ 0 | Lost |
| Playing | 计时 ≥ 60s | Won |
| Won/Lost | `RestartGame` | Playing（全量重置） |
| Won/Lost | `BackToMenu`（可选，**未实现**；M4.5 §3 主菜单需要新状态） | Ready |

规则：

- `GameManager` 是唯一可以改状态的类；其他系统只订阅/查询。
- 暂停统一用 `Time.timeScale = 0f`，恢复时置 1；**不得**用协程里手动判断 `isPaused` 拼凑（容易漏）。
- 使用 `Time.unscaledDeltaTime` 的只有动画/UI，游戏逻辑一律 `Time.deltaTime`，保证暂停时计时冻结。
- **不建议** `SceneManager.LoadScene` 重开：WebGL 下重载有声有色但更重，且不好判断初始化时序。改为 `GameManager.Restart()` 调用各系统的 `Reset()`。若选择重载场景，则必须保证所有单例/静态状态都清空，并在验收清单里加"重开 3 次无异常"。

### 5.2 职责边界

| 类 | 职责 | 禁止 |
|---|---|---|
| `GameManager` | 状态机、开始/暂停/结束流程、协调 | 不处理输入、不写分数算法 |
| `PlayerController` | 读取 `PlayerInput`，移动刚体 | 不改状态机 |
| `PlayerHealth` | HP、受伤、无敌帧、死亡事件 | 不直接调 UI |
| `EnemySpawner` | 定时生成、上限控制、清场 | 不追踪玩家 |
| `EnemyAI` | 追踪玩家、接触伤害 | 不判断胜负 |
| `ScoreService` | 分数计算与结算 | 不碰 UI |
| `HUD` | 显示分数/时间/HP | 不写游戏逻辑 |
| `WebGLBridge` | 收发 H5 消息，做边界转换 | 不写玩法逻辑 |

### 5.3 引用与通信

- 全部用**序列化字段显式引用**（`[SerializeField]`），禁止在 `Update` 里 `FindObjectOfType` / `GameObject.Find`。
- 跨模块通知用 C# `event` 或 `Action`（如 `PlayerHealth.OnDied`），不要用 `SendMessage` 做内部通信（`SendMessage` 只留给 H5 桥接）。
- 不引入 DI 框架、不用 ECS、不用第三方状态机库。一个人的项目，**可读性 > 抽象度**。

### 5.4 数值集中管理

- 所有可调数值放一个 `GameConfig`（ScriptableObject）或静态常量类：玩家速度、HP、敌人速度、生成间隔、伤害、无敌时间、总分规则。
- 场景里只放引用，不藏魔法数字（`speed = 3.2f` 这种必须有出处）。
- README 的"玩法规则"必须与 `GameConfig` 一致；改数值时同步改文档。

### 5.5 输入抽象（2026-10-31 现状）

```text
PlayerInputSource (抽象)
  ├── KeyboardInput      // WASD / 方向键
  └── TouchInput         // 锚点相对拖动（浮动摇杆逻辑，不画固定摇杆）
PlayerInputRouter        // 触控优先，否则键盘；平台判断只在这里
PauseHotkey              // Esc / P：Playing → Pause；Paused → 请求 3-2-1 恢复
```

- 输入层只输出 `Vector2 Move`；`PlayerController` 只依赖基类，不做平台判断。
- 触控：按下点为摇杆中心；`maxRadius = 0.2 × 屏高`（夹 80～160 设备像素）；死区 8px；松手归零；
  只跟踪第一根手指，换手指重新锚定。详见 `docs/实现总览.md` §4。
- 摇杆可视化（M4.7）只加视觉，不改上面的算法；桌面鼠标不显示。
- **桌面必须有键盘暂停/继续**：Esc 和 P 都支持；Esc 在全屏时可能被浏览器用于退出全屏，所以 P 不能省。
  暂停状态由 `GameManager` 决定，H5 只发请求、显示文案，不在 H5 里绑键。
- 移动端必须有可玩的触控方案——"页面适配手机"如果游戏不能玩，等于没做。这是**必做项**，不是加分项。
- 触摸用 Unity 内置的 `Input.touchCount` / `Input.GetTouch` 即可，不用引入新 Input System（减少配置风险）。

## 6. 游戏规则与数值定义

需求只说"显示分数和剩余时间"，**必须把规则钉死**，否则验收时各说各话。

### 6.1 计分

```
存活分 = 已存活整数秒 × 10
击杀分 = 击杀数 × 20
胜利奖励 = 200（仅胜利时）
最终分数 = 存活分 + 击杀分 + 胜利奖励
```

- 时间显示：剩余时间 `回合时长 - 已存活秒数`，向上取整到整数秒，格式 `mm:ss`（60 秒 → `01:00`，0 → `00:00`；
  回合时长变化时自动进位，不再硬编码 `00:` 前缀）。
- HP 显示为 `100/100` 或血条，二选一（建议血条 + 数字）。

### 6.2 默认数值（写进 `GameConfig`）

| 参数 | 默认值 | 备注 |
|---|---|---|
| 玩家 HP | 100 | |
| 玩家速度 | 3.2 单位/秒 | |
| 敌人基础速度 | 1.8 单位/秒 | 必须慢于玩家，否则必死 |
| 敌人初始生成间隔 | 1.5 秒 | |
| 生成间隔递减 | 每 10 秒 −0.15 秒，下限 0.5 秒 | |
| 同屏敌人上限 | 20 | 防止低端机卡死 |
| 接触伤害 | 12 | |
| 受伤无敌时间 | 1.0 秒 | 防止一帧多次判定 |
| 地图尺寸 | 36×20 世界单位（约 2×2 屏） | **地图大于视野**；相机跟随玩家并钳制在地图内 |
| 生成位置 | 玩家周围约 1.15×相机半对角线、且必须在相机视野外 | 相机跟随有滞后，只按相机视口算会在边缘"脸上刷怪" |
| 敌人速度扰动 | ±12%（单类型占位） | 1.58～2.02，上限 2.2；玩家 3.2 |
| 敌人重叠解算 | 位置修正，`minDist ≈ 0.9～1.0`（视觉直径） | AI 只 seek；Spawner 每帧 1～2 轮两两推开；不再叠加 1/d² 分离力 |
| 敌人停距 / 站位 | 约 0.7 + 8～12 个站位角 | 避免全部挤玩家中心；接触伤害仍由 Trigger 判定 |
| 回收 | 离开相机视野（含 0.05 margin）持续 3 秒 | 释放名额；回收只在屏幕外发生，玩家看不见 |
| 压力曲线 | 敌人速度随局内时间 1.0→1.15 | 作用于**已存在**敌人；上限达到后仍能加压，最终仍 ≤ 2.2 |
| 敌人变体上限 | 2（基础 + 可选快速/近战变体） | 不做 Boss/远程弹幕；变体只改速度/外观/伤害 |
| 胜利条件 | 存活 ≥ 60.0 秒 | |
| 失败条件 | HP ≤ 0 | |

### 6.3 边界规则

- **玩家边界 = 地图边界，不是相机视野边界**。M4-B0 起地图 36×20，玩家可走出一屏；相机在 `LateUpdate` 平滑跟随并钳制在地图内，玩家始终可见。
- 地图边缘必须有可见的视觉边界（背景/网格到此结束），不能是"看不见的空气墙"。
- 敌人之间必须做重叠解算（优先位置修正），不允许长期重叠或持续抖动；AI 只负责 seek，
  不用 steering 分离力实现；停距/站位环见 `docs/玩法增强.md` 2.1。
- 敌人**离开相机视野**并持续 3 秒 → 回收并释放生成名额。不要再用"距玩家 >1.5 屏/25 单位"：单屏时期的活动范围只有约 22.8，那个阈值永远不触发。
- 生成点必须在相机视野外，且距玩家有下限（约 1.15×相机半对角线）：相机跟随时会滞后，只按相机视口算会在相机前方的地图边缘"脸上刷怪"。
- 敌人行为扩展（多种速度、包围、变体）只能在移动端 P0 验收后做，且最多 2 种变体；不做 Boss/远程弹幕。
- 暂停时：计时、生成、移动、AI 全部冻结；恢复后从原状态继续。
- 桌面键盘：`Esc` / `P` 暂停；恢复（含失焦暂停后）**先走 3-2-1 再继续**（M4.6）。
  `Esc` 在全屏时可能被浏览器用于退出全屏，所以 `P` 必须同时可用。
- 失焦/切后台：自动暂停；切回**保持暂停**，不自动恢复；玩家点继续/按 P 才倒数。
- 重开时：分数、时间、HP、敌人列表、无敌计时、生成计时、相机位置**全部归零**。

## 7. H5 ↔ Unity 通信协议

> 这一节是项目的"接口契约"，必须单独写到 `docs/bridge-protocol.md`，代码和文档同步改。

### 7.1 加载方式（关键决策）

**不用 iframe。** 用 Unity 的 `createUnityInstance` 把游戏直接挂到我们自己的页面上：

```html
<canvas id="unity-canvas"></canvas>
```

```js
const instance = await createUnityInstance(canvas, config, onProgress);
```

理由：

- 同页面才能直接拿到 `unityInstance` 调 `SendMessage`，也才能让 Unity 直接调 `window` 上的函数；
- iframe 方案需要 `postMessage` + 跨文档权限，调试成本翻倍，且移动端高度计算更麻烦。

**备选（不推荐，仅兜底）**：若自定义外壳加载失败，保留 Unity 默认生成页作为 `web/unity/index.html` 备用预览。

### 7.2 命名与入口

| 方向 | 机制 | 约定 |
|---|---|---|
| H5 → Unity | `unityInstance.SendMessage(go, method, arg)` | 目标 GameObject 固定名 **`WebGLBridge`**，且必须处于激活状态 |
| Unity → H5 | `.jslib` 调用 `window.SurvivalGameBridge.*` | 页面脚本**必须先注册** `window.SurvivalGameBridge`，再加载 Unity |

**注意 `SendMessage` 的限制：** 只能传 **1 个参数**，且只能是 string / int / float。传对象一律先序列化成 JSON 字符串。

### 7.3 H5 → Unity 方法表

| 方法 | 参数 | 说明 |
|---|---|---|
| `StartGame` | `nickname: string` | 从 Ready 进入 Playing；昵称同时传给 Unity 显示 |
| `PauseGame` | 无 | Playing → Paused |
| `ResumeGame` | 无 | Paused → Playing |
| `RestartGame` | 无 | Won/Lost → Playing，全量重置（昵称沿用） |
| `SetPausedByVisibility` | `"true"/"false"` | 标签页切换时自动暂停/恢复 |

实现侧：C# 方法必须是 `public void MethodName(string arg)`，参数用 string 兼容性最好。

### 7.4 Unity → H5 事件表

页面侧统一入口：

```js
window.SurvivalGameBridge = {
  onReady,        // Unity 场景加载完成，可以开始
  onGameOver,     // 一局结束（只发一次）
  onStateChange,  // 状态变化（可选，调试用）
  onProgress      // 加载进度 0~1（可选）
};
```

| 事件 | 载荷 | 触发时机 |
|---|---|---|
| `onReady` | `{ protocol: 1 }` | 第一帧初始化完成后，仅一次 |
| `onGameOver` | 见下方 schema | 胜利或失败时，**每局仅一次** |
| `onStateChange` | `{ state: "Playing" \| "Paused" \| ... }` | 可选 |

**`onGameOver` 数据契约：**

```json
{
  "protocol": 1,
  "event": "gameOver",
  "payload": {
    "result": "win",
    "score": 1240,
    "survivedSeconds": 60.0,
    "kills": 12,
    "nickname": "阿宝",
    "breakdown": {
      "survival": 600,
      "kills": 240,
      "winBonus": 200
    }
  }
}
```

### 7.5 协议纪律

1. **版本号**：`protocol: 1`。加字段可以，改字段语义必须升版本；JS 端必须容忍未知字段。
2. **时序**：H5 在加载 Unity **之前**注册好 `window.SurvivalGameBridge`；Unity 加载完成后才发 `onReady`；在 `onReady` 之前，Start 按钮禁用。
3. **幂等**：`onGameOver` 在 Unity 侧加 `bool _reported` 守卫，每局只发一次；H5 侧对重复事件也做守卫（双保险）。
4. **异常隔离**：Unity 调用 JS 时用 `try/catch` 包裹，JS 异常不能导致 Unity 崩溃；H5 侧收到非法 JSON 时只记日志，不崩页面。
5. **不传运行时对象**：所有跨边界数据必须是 JSON 可序列化的原始值。
6. **字符串安全**：昵称在 Unity 侧只用于显示，**不回传 HTML**；H5 渲染昵称用 `textContent`，禁止 `innerHTML`（防 XSS）。

### 7.6 编辑器与网页兼容

```csharp
#if UNITY_WEBGL && !UNITY_EDITOR
    [DllImport("__Internal")] private static extern void NotifyGameOver(string json);
#else
    private static void NotifyGameOver(string json) => Debug.Log($"[Bridge] {json}");
#endif
```

- 这样在 Editor 里也能完整跑玩法，不需要每次构建才能测。
- Editor 下用 `Debug.Log` 模拟 H5 消息，方便对照。

## 8. H5 外壳规范

### 8.1 页面状态机

```text
Loading ──(onReady)──▶ Ready ──(Start)──▶ Starting ──(onStateChange Playing)──▶ Playing
                                                                                  │
                                                                      ┌───────────┴───────────┐
                                                                      ▼                       ▼
                                                                    Paused                 Result(Win/Lose)
                                                                      │                       │
                                          继续/Esc/P → 3-2-1 → Playing   ├──(重新开始)──▶ Playing
                                                                              └──(刷新最高分提示)
```

- 页面状态与 Unity 状态**由 Unity 广播驱动**，H5 不自己猜；`Starting` 是等待 Unity 确认的过渡态。
- 失焦 → `Paused`；切回**仍保持 Paused**，玩家点继续/按 P 后才开始 3-2-1。
- 刷新页面 = 回到 Loading（最高分从 localStorage 读回）。

### 8.2 版式与响应式（必做）

- 移动优先；主容器 `max-width: 960px; width: 100%; margin-inline: auto;`
- 游戏区固定 **16:9** 比例（`aspect-ratio: 16 / 9`），超宽屏时两侧留黑，不拉伸变形。
- 使用 `height: 100dvh`（不是 `100vh`）避免手机地址栏遮挡；`padding` 避开 iOS 安全区：`env(safe-area-inset-*)`。
- 手机横屏时提示"横屏体验更佳"（或直接隐藏外层信息，最大化游戏区）。
- 按钮最小点击区 **44×44px**；输入框 `font-size: 16px` 起（防 iOS 自动缩放）。
- 桌面与手机**同一套代码**，媒体查询只调 `padding` / 字号 / 布局方向，不做两套页面。

### 8.3 页面元素

| 区域 | 内容 |
|---|---|
| 顶部 | 标题 + 昵称输入（首次进入可预填上次昵称） |
| 操作提示 | 桌面：`WASD / 方向键移动 · Esc / P 暂停`；手机：`拖动屏幕移动 · 点画面内「暂停」`；目标：`躲开敌人，存活 60 秒` |
| 中部 | Unity 画布容器 + 加载进度条 + 遮罩层 |
| 底部 | 本次成绩、历史最高分、操作按钮 |
| 页脚 | `版本号 · 构建时间` |

> 操作提示放在 H5（DOM 文本），不要塞进 Unity HUD：不占字体图集、不触发重烤，中文随便改。提示文案按输入设备切换（`pointer: coarse` 或 `max-width`），不要在触控未实现时对手机写"拖动"。

### 8.4 健壮性

- **localStorage 不可用**（隐私模式/被禁用）：`try/catch` 包住所有读写，回退到内存变量，游戏照常能玩，页面提示"本次成绩无法保存"。
- **Unity 加载失败**（404 / wasm 被拦截 / 内存不足）：显示错误卡片 + "重试"按钮，不能白屏。
- **不依赖 CDN**：字体、图标、脚本全部本地，断网也能跑。
- **无轮询**：H5 不每帧读 Unity 状态，只处理事件；HUD 数字在 Unity 内绘制。
- 页面 `console` 零报错是验收项。

### 8.5 可访问性

- `<label for>` 绑定昵称输入；`aria-live="polite"` 播报结算结果。
- 所有按钮是 `<button>`，不是 `<div onclick>`。
- 可见的 `:focus-visible` 样式；尊重 `prefers-reduced-motion`。

## 9. 本地存储规范

### 9.1 Key 命名

统一前缀 `survival.`，带版本后缀：

| Key | 类型 | 说明 |
|---|---|---|
| `survival.bestScore` | string(number) | 历史最高分 |
| `survival.nickname` | string | 上次使用的昵称 |
| `survival.history` | JSON string | 最近 20 局记录（可选） |

### 9.2 规则

- 全部走 `storage.js` 封装，**禁止在业务代码里直接写 `localStorage.setItem`**。
- 读取时 `JSON.parse` 必须 `try/catch` + 类型校验；数据损坏时静默重置，不能让页面崩。
- 写入失败（配额满）要捕获，不影响当前对局。
- **最高分判定**：`newScore > bestScore` 才更新；相等不算新纪录。
- 可选增强（P2）：按昵称记录个人最高分；历史记录列表。**不是必须项**，别在没做完核心前做。

### 9.3 刷新后仍在（验收关键点）

- 刷新 → 页面 `Loading` → `Ready` 时读取 `survival.bestScore` 并显示。
- 清空浏览器存储 → 最高分回到 `0`，页面不报错。

## 10. 代码与资源命名规范

### 10.1 C#

- 类型/方法/属性：`PascalCase`；局部变量/参数：`camelCase`。
- 私有字段：`_camelCase`，配 `[SerializeField]`。
- 一个文件一个 `MonoBehaviour`，文件名与类名**完全一致**。
- 命名空间：`Survival.Core` / `Survival.Player` / `Survival.Enemy` / `Survival.UI` / `Survival.Bridge`。
- 不写 `public` 字段（除 ScriptableObject 数据类），暴露用属性。
- 日志用统一包装 `Log.Info/Warn/Error`，发布构建可整体关闭。
- 每帧 `Update` 里不做字符串拼接、`GetComponent`、`Find`、LINQ 分配。

### 10.2 JS

- ES Module + `"use strict"`；全局只暴露 `window.SurvivalGameBridge` 一个入口。
- 导出函数写 JSDoc（参数、返回、副作用）。
- 常量放 `js/constants.js`（key 名、事件名、版本号），避免字符串散落。
- 不用 `var`；异步统一 `async/await`；错误必须处理（`try/catch` 或 `.catch`）。

### 10.3 资源命名

| 类型 | 前缀 | 示例 |
|---|---|---|
| Sprite | `spr_` | `spr_player_idle.png` |
| Prefab | `pfb_` | `pfb_enemy_basic.prefab` |
| Scene | `scn_` | `scn_Game.unity` |
| ScriptableObject | `cfg_` | `cfg_GameConfig.asset` |
| Material | `mat_` | `mat_player.mat` |
| Audio | `sfx_` / `bgm_` | `sfx_hit.wav` |
| 脚本 | 无前缀 | `PlayerHealth.cs` |

- 像素风：`Filter Mode = Point`、`Compression = None`、`PPU = 100`。
- 非像素风可用 `Bilinear`，但同项目内风格必须统一。

### 10.4 文件格式

- 文本文件 UTF-8 无 BOM，换行统一 LF（用 `.gitattributes` 固定）。
- 二进制资源 > 50MB 用 Git LFS（本项目一般不会触发，但先写进规范）。

## 11. WebGL 构建规范

### 11.1 Player Settings 必选项

| 设置 | 值 | 原因 |
|---|---|---|
| Platform | WebGL | |
| Compression Format | **Brotli** | 体积最小 |
| Decompression Fallback | **开启** | 否则静态服务器没配 header 就加载失败 |
| Managed Stripping Level | **Medium** | 平衡体积与兼容性 |
| Strip Engine Code | **开启** | |
| IL2CPP Code Generation | 默认 | |
| Color Space | **Gamma** | 2D 简单场景更稳，体积略小 |
| API Compatibility | **.NET Standard 2.1** | |
| Enable Exceptions | **Explicitly Thrown Exceptions Only**（或关闭） | 显著减小体积 |
| Resolution | 1280×720，Resizable Canvas | |
| Run In Background | 关闭 | 节能 |
| WebGL Template | **Minimal** 或 **None** | 我们用自己的外壳页 |
| Build 输出路径 | `web/unity/` | 见目录规范 |

> 注意：`Decompression Fallback` 会让 Unity 走 JS 解压，首次加载略慢但"到处都能跑"。如果你能控制服务器（比如 Nginx 配 `Content-Encoding`），可以关掉以换取更快加载——**二选一，并在 README 写明**。默认建议打开，交付优先。
>
> **现状（2026-10-31）**：M4/M5 尚未改构建参数；`Managed Stripping` / 关闭 Decompression Fallback 属于 M5 评估项，
> 先实测包体与加载时间再改，不要凭感觉动。

### 11.2 体积与性能预算

| 指标 | 预算 |
|---|---|
| 首次加载总量（brotli 后） | ≤ 15 MB |
| 4G 环境首次可玩时间 | ≤ 15 秒 |
| 桌面帧率 | ≥ 60 FPS |
| 中端手机帧率 | ≥ 30 FPS |
| 同屏敌人 | ≤ 20 |

- 移动端 `devicePixelRatio` 限制在 **1.5~2**，超过就降采样，避免高分屏把 GPU 拖死。
- 不使用实时阴影、后处理、粒子海；2D 用 SpriteRenderer 就够了。

### 11.3 可复现构建

- 提供 `Assets/Editor/BuildScript.cs`，静态方法 `BuildWebGL()`，用命令行可调：

```bash
Unity -quit -batchmode -projectPath ./unity \
      -executeMethod BuildScript.BuildWebGL \
      -logFile build.log
```

- 构建前**清空** `web/unity/` 旧产物，避免新旧文件混在一起。
- 构建后检查 `web/unity/` 内文件名（Unity 6 的 loader 名可能是 `*.loader.js`，不同版本命名有差异，以实际产物为准，并写进 README）。
- 把 Unity 版本、构建日期、Build 名写进 `web/unity/` 旁的 `build-info.json`，H5 页脚读取展示。

## 16. 风险清单与取舍

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| WebGL 构建失败/报错 | 中 | 高 | M0 先验证；锁定 Unity 版本；构建日志入档 |
| 本地静态服务器缺 header 导致加载失败 | 高 | 高 | 开 `Decompression Fallback`；README 写清启动方式 |
| `SendMessage` 时序早于 Unity 就绪 | 中 | 高 | `onReady` 前禁用 Start；按钮状态由事件驱动 |
| `onGameOver` 重复触发导致最高分算错 | 中 | 中 | Unity `_reported` 守卫 + H5 幂等 |
| 手机高分屏掉帧 | 中 | 中 | 限制 DPR、敌人上限、关闭后处理 |
| iOS Safari 隐私模式 localStorage 抛异常 | 中 | 中 | 全部 try/catch + 内存回退 |
| 触控方案拖慢进度 | 中 | 中 | 用内置 Touch API，不做摇杆美术 |
| 范围蔓延（道具、排行榜、多敌人） | 高 | 高 | 见第 17 节"明确不做" |

**取舍原则：先保证"必须完成"的 5 条全绿，再谈体验。**
