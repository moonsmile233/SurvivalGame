# 玩法增强（在最低要求之上）

> 文档版本：2026-10-31T15:25+08 · 作者：军师 · 改前必须从磁盘重读；上下文旧副本作废。

> 原则：**先保证原始需求 17 条全绿，再让 60 秒更好玩**。本文件所有条目排在 M3（H5 闭环）验收之后；M3 未绿不动这里。

## 0. 与原始需求的关系

原始需求只要求：敌人定时生成、追踪玩家、玩家被攻击掉血、存活 60 秒、支持失败/重开/暂停、显示分数与时间。**没有规定敌人必须重叠、必须直线叠成一坨、只能有一种移动方式**。因此：

- 分离、速度差异、包围站位、近战攻击：**不冲突**。
- 真正冲突的是我们自己的规范：原 §6.3「敌人可以重叠」、原 §17「不做多种敌人类型」。**已同步修改**为软分离 + 最多 2 种变体，不偷偷改实现。
- 时间风险才是唯一的冲突：所以 P0 放 M4，P2（近战变体）只在 M4 有余力时做。

## 1. 优先级

| 级别 | 内容 | 时机 |
|---|---|---|
| P0 | 敌人软分离、速度扰动、远距离回收 | M4 前段 |
| P1 | 包围站位、上限下的生成节奏 | M4 中段 |
| P2（可选加分） | 1 种近战变体（靠近→前摇→挥砍）、attack slot、轻微镜头震动/音效 | M4 后段，必须不挤占 M5 |
| 不做 | Boss、道具、技能树、远程弹幕、A*/流场、动态刚体推挤、对象池 | — |

## 2. P0：让敌群不叠成一团

### 2.1 拥挤分离（B1 重做；先做这个，再做压力曲线）

**为什么现在的会抖**：初版是"1/d² 推力加到 seek 上再归一化"：

- `push += offset / sqrDistance` 在距离趋近 0 时极陡，三只以上互相推，下一帧方向又翻转；
- `StanceOffset 0.6 × StanceWeight 0.3 = 0.18`，所谓包围站位实际只把目标点偏离玩家 0.18 单位，
  所有敌人仍在抢玩家中心一个点；
- 没有速度平滑，方向每帧可以瞬间翻转；
- 占位 sprite 是 1 单位宽，而分离半径只有 0.76，视觉上本来就会交叠。

**Brotato 这类游戏为什么稳**：不是"分离力调得更好"，而是**用碰撞/位置解算直接消除重叠**，AI 只负责"往哪走"；
敌人也各有停距/攻击距离，不会全部冲向玩家中心。（Brotato 未公开完整源码，这里按同类游戏的通用实现说明。）

**改法（按优先级，全部在 B1）**：

1. **位置修正代替分离力（首选）**
   - `EnemyAI` 只做 seek + 站位角，不再把 separation 加进移动方向；
   - `EnemySpawner` 每帧做 1～2 轮两两重叠修正：`minDist = 0.9～1.0`（与视觉半径一致），每对沿连线各推开一半；
   - 20 只 O(n²) = 400 次/帧，无分配；位置修正不会过冲，不会抖。
2. **停距 + 站位环**
   - 追到 `playerRadius + enemyRadius - 0.08`（约 0.7）就停；按 8～12 个站位角分布到环上，接触伤害仍由 Trigger 触发；
   - 现在的 `Lerp(player, standPoint, 0.3)` 等于没站位，改成直接瞄准 `player + dir × 0.7`。
3. **攻击名额（可选，Brotato 式）**
   - 最多 6 只在伤害环内，其余在 1.2～1.5 的环上等待；名额空出再进。避免 20 只同时压在玩家身上。
4. **视觉匹配**
   - 占位 sprite 1 单位宽，`minDist` 至少 0.9～1.0；换正式素材后按视觉半径调。
5. **若坚持保留 steering 分离**
   - 用线性衰减 `(1 - d/r)`，不要 1/d²；权重 0.6～0.8；只取最近 4～6 个邻居；速度做平滑；
     禁止分离把方向推到 seek 的反方向。
6. **不推荐改动态 Rigidbody**：20 只不值得；接触伤害、玩家推挤、暂停时序都要重测。

验收：

- 20 只挤在玩家周围时**没有持续抖动**，不会长期重叠；视觉上能分辨个体。
- 玩家被围住时仍有缝隙、能移动，不会一帧多次判定（无敌帧仍生效）。
- 站位环能形成；玩家移动时敌人跟随，不出现"推回去再追上来"的反复。
- 60 FPS（桌面）/ 30 FPS（中端手机）；稳定后 `Update` 无 GC、位置修正无分配。

### 2.2 速度扰动

- 单类型阶段：生成时 `speed *= Random.Range(0.88f, 1.12f)`；基础 1.8 → 1.58～2.02。
- 上限 2.2；玩家 3.2，必须始终追不上玩家。
- 多类型阶段：速度写在 `EnemyDefinition` 里，不用全局随机。

验收：敌人到达时间有明显前后梯队，不再一整坨同时压上来。

### 2.3 视野外回收（地图大于视野后才成立）

**前提（M4-B0 已定）**：地图 36×20，相机跟随玩家，玩家活动范围不再等于视野。单屏时期活动范围最大只有约 22.8，原来的「1.5 屏 / 25 单位」阈值永远不触发，等于没写。

方案：

- 敌人**离开相机视野**（viewport ±0.05）并持续 3 秒 → 销毁，并从 Spawner 列表移除，释放名额。
- 新生成的敌人从视野外进入约 0.8～1.5 秒；3 秒计时不会误杀刚出生的敌人。
- Spawner 增加 `Unregister/Recycle`；`ClearEnemies` 之外不残留 null。
- 回收只发生在玩家看不见的地方，不凭空删玩家眼前的敌人。

验收：

- 玩家跑动/绕圈时，身后离屏超过 3 秒的敌人被回收，新敌人从视野外补进；同屏始终 ≤ 20。
- 站着不动时敌人不会被回收，20 只上限仍然有效。
- 重开后列表和相机都清零。
- **20 上限不再等于后期停止刷怪**：上限 + 回收 + 压力曲线共同决定压力。

## 3. P1：让追击看起来"有脑子"

### 3.1 包围站位

- 每只敌人生成时分配一个随机"站位角"。
- 距玩家 < 3 单位时，目标点 = 玩家位置 + 0.6 单位 × 该方向；与直接 seek 混合（偏移权重 30%）。
- 分离力负责解决重叠，站位角负责避免所有敌人挤在同一条直线。

验收：玩家至少被两个方向同时逼近；不会出现 20 只排成一条线。

### 3.2 上限下的生成节奏

- 满 20 时不再排队；靠视野外回收释放名额。
- 生成间隔仍按 1.5s → 0.5s 递减，不额外加速。
- 不为"上限"提高 `EnemyLimit`；移动端 20 是预算。

### 3.3 压力曲线（Brotato 式）

上限 20 且没有击杀时，后半局不能只靠"生成间隔递减"：第 20 只约在 27 秒生成，之后间隔再降也不再生效。压力要作用在**已存在的敌人**上：

- 敌人速度随局内时间从 1.0 → 1.15（再夹到 2.2 上限），在 `EnemyAI.Update` 里乘；**不要在生成时一次性算死**，否则 27 秒后没有新敌人，曲线无效。
- 可选：30 秒来一次"涌潮"（一次补 3～4 只），只在实测后半局太平淡时加；不新增中文 UI 文案。
- 不用提高 `EnemyLimit` 解决（20 是移动端预算），不用减无敌帧/加伤害硬造难度。

验收：30～60 秒敌人到达节奏明显变紧，但玩家仍能靠走位拉开；5 局人工胜率 40%～80%。

## 4. P2：近战敌人变体（可选）

> 只在 M3/M4 核心全绿、且 M5 时间充足时做；最多 1 种，不做第二种。

### 4.1 数据

新增 `EnemyDefinition` ScriptableObject：

| 字段 | 基础追击怪 | 近战变体 |
|---|---|---|
| sprite | 现有 | 新素材（M4） |
| moveSpeed | 1.8 | 1.6 |
| contactDamage | 12 | 0（不靠碰撞） |
| attackType | Contact | Melee |
| attackRange | — | 1.2 |
| windup | — | 0.35s |
| cooldown | — | 1.2s |
| damage | — | 15 |
| stopDistance | 0 | 0.9 |

Spawner 改为持有 `EnemyDefinition[]`（先放 1～2 个），按权重选；根据 `attackType` 组装组件。

### 4.2 结构

- `EnemyAI` 只负责移动（追到 `stopDistance`）。
- `ContactAttack`：把现有 `OnTriggerStay2D` 搬出去。
- `MeleeAttack`：状态机 `Approach → Windup → Strike → Recover → Cooldown`。
  - Windup 期间明显提示（变色/缩放），玩家有机会走开。
  - Strike 那一帧做一次距离 + 朝向夹角检查；命中才 `TakeDamage`；一次挥砍只结算一次。
  - 用 `Time.deltaTime`，不用协程/材质实例；每帧无分配。
- `EnemyView`：订阅前摇/出手事件做表现，逻辑不碰 SpriteRenderer。
- Attack slot：最多 2 只近战同时进入攻击距离，其余在环上等。

验收：

- 玩家能在前摇期间走出攻击范围，不掉血。
- 一次挥砍只掉一次血；无敌帧仍然有效。
- 近战怪和基础怪可以同屏；总数仍 ≤ 20。
- 不改 `GameManager`、`ScoreService`、`PlayerHealth`、`PlayerController`。

## 5. 参考：其他游戏怎么解决

- **Brotato（土豆兄弟）**：地图大于视野、相机跟随、敌人从视野外生成；波次有预算和时限，难度靠敌人属性/数量/组合上升；手机版用浮动摇杆。
  我们借的是**大地图 + 相机跟随 + 视野外生成/回收 + 压力曲线 + 浮动摇杆 + 敌人可读性**；
  **不借**自动攻击、武器、道具、商店、角色 build、Boss（都不在作业要求内，会把 60 秒作业变成另一个项目）。
- **Vampire Survivors**：反过来，允许大量重叠，靠海量击杀和 AoE 清场；不适合"躲避"型玩法。
- **RTS/大规模人群**：Flow Field + 局部避让（ORCA/RVO）；20 只怪用不上。
- 结论：空旷竞技场不需要 A*/流场，问题是**局部避让 + 名额策略**。
