## 0. 30 秒摘要

- Unity 6（`6000.3.22f1`）+ Built-in 2D，WebGL2；H5 是原生 HTML/CSS/JS，无框架、无构建。
- 单场景 + `GameManager` 显式状态机；重开调用 `Reset()`，不重载场景。
- 玩家在 36×20 地图上躲避追踪敌人，存活 60 秒胜利；同屏最多 20 只；相机跟随并钳制在地图内。
- H5 负责昵称、开始、加载、结算、最高分（localStorage）；Unity 负责玩法与状态。
- 当前线上：Netlify（M4.6 构建），国内托管未执行；`web/unity/` 仅在本地构建时存在，尚未随仓库交付。

## 2. 玩法规则与数值

### 2.1 计分

```
存活分 = 已存活整数秒 × 10
击杀分 = 击杀数 × 20        // 当前没有攻击手段，Kills 恒为 0，接口保留
胜利奖励 = 200（仅胜利）
最终分 = 存活分 + 击杀分 + 胜利奖励
```

- 60 秒胜利、无击杀时：`60×10 + 200 = 800`。
- 剩余时间显示 `60 - 已存活秒数`，向上取整；格式 `00:60`～`00:00`（开局瞬间显示 `00:60`，已知小瑕疵）。

### 2.2 数值（以 `GameConfig` / `EnemyDefinition` 为准）

| 参数 | 值 | 说明 |
|---|---|---|
| 玩家 HP | 100 | |
| 玩家速度 | 3.2 单位/秒 | |
| 受伤无敌 | 1.0 秒 | 防止一帧多次判定 |
| 敌人基础速度 | 1.8 | 单类型 `def_Enemy_Chaser.asset` |
| 敌人接触伤害 | 12 | |
| 敌人碰撞半径 | 0.38 | 分离/停距派生 |
| 生成间隔 | 1.5 秒起，每 10 秒 −0.15，下限 0.5 | |
| 同屏上限 | 20 | |
| 速度扰动 | ±12%，上限 2.2 | 玩家 3.2，始终更快 |
| 敌人间距 | 0.95，两两位置修正 2 轮/帧 | 不做 steering 分离力 |
| 停距/站位 | 约 0.7 + 12 个站位槽（±0.06 rad 抖动） | 接触伤害仍由 Trigger 判定 |
| 回收 | 离相机视野（±0.05）持续 3 秒 | 进过视野后才计时 |
| 压力曲线 | 速度 × `Lerp(1, 1.15, elapsed/60)` | 作用于已存在敌人 |
| 地图 | 36×20 世界单位 | 约 2×2 屏 |
| 单局时长 | 60 秒 | |

> 这些是**本项目的设定值**；参考了同类节奏（Brotato 波次压力、20 Minutes Till Dawn 的走位生存），
> 但不是同类原值，也没有做过 5 局人工平衡统计（见 §9）。

## 3. 状态机与暂停/恢复

### 3.1 状态

```
Booting ──初始化完成──▶ Ready ──StartGame(H5)──▶ Playing
                                                  │  ▲
                                      PauseGame   │  │  玩家恢复（继续 / Esc / P）→ 3-2-1 → ResumeGame
                                                  ▼  │
                                                Paused
Playing ──HP ≤ 0──▶ Lost ──RestartGame──▶ Playing（全量重置）
Playing ──60s──▶ Won ──RestartGame──▶ Playing（全量重置）
```

- 只有 `GameManager` 能改状态；`Time.timeScale = 0` 用于 Paused/Won/Lost，`ResetRound` 先恢复 1。
- 玩法逻辑用 `Time.deltaTime`；暂停/结算冻结。UI 用 uGUI，不受 timeScale 影响。
- 重开不走 `SceneManager.LoadScene`，`RestartGame()` 重置分数/时间/HP/敌人/生成计时/相机。
- 没有 `Menu` 状态；主菜单/难度（M4.5 §3）未实现。

### 3.2 暂停/恢复（M4.6 语义）

| 场景 | 行为 |
|---|---|
| 手动暂停（按钮 / Esc / P） | Playing → Paused，`timeScale=0` |
| 窗口失焦 / 标签页隐藏 / 切 App | 自动暂停；**切回仍保持 Paused**，不自动继续 |
| 玩家点「继续」/ 按 P 或 Esc | **先 3-2-1 倒计时（`unscaledDeltaTime`），结束才 `ResumeGame()`**；手机用来把手指挪回屏幕 |
| 倒计时中重复按 P/Esc | 忽略（不加速、不取消） |
| 倒计时中再次失焦 | 停表、保持 Paused；切回后需重新点继续 |
| 失焦时处于 Ready/结算 | 不误触发暂停 |

- H5 侧监听 `blur` / `focus` / `visibilitychange`，按最后发送值去重；失焦发 `"true"`，切回发 `"false"`。
- `SetPausedByVisibility("false")` **只清标记**，不请求倒计时、不恢复。
- 依据：网页游戏通行的“return state”（回到页面必须用户手势恢复），见 §10；3-2-1 是本作针对手机手位的刻意差异。

## 4. 输入

- **键盘**：WASD / 方向键；`PlayerInputSource` 抽象，`PlayerInputRouter` 在有触控时优先触控。
- **触控（手机）**：锚点相对拖动（浮动摇杆逻辑，不画固定摇杆）
  - 手指按下点 = 摇杆中心；`Move = clamp((current-anchor)/maxRadius, 1)`；
  - `maxRadius = clamp(Screen.height × 0.2, 80, 160)` 设备像素；死区 8px；松手归零；
  - 只跟踪第一根手指，记录 `fingerId`；换手指重新锚定；
  - 鼠标按住拖动走同一逻辑（Editor/桌面兼容）。
- **摇杆可视化（M4.7）**：按下时显示外圈 + 摇杆头，松手/暂停/离开 Playing 隐藏；只加视觉，不改上面的算法；
  桌面鼠标不显示。可视半径先取 **0.65 × 输入 maxRadius**（0.55～0.70 真机可调）；**外圈是视觉参考，不是满速边界**。
- **暂停快捷键**：桌面 `Esc` / `P`；全屏时 Esc 可能被浏览器用于退出全屏，所以 P 必须可用。
- 依据：同类手机游戏普遍使用浮动/可见摇杆（Brotato 手机版、20 Minutes Till Dawn 移动版）；本作先保证手感与实现风险，再补视觉。

## 5. 地图 / 相机 / 敌人

- **地图**：36×20；玩家边界 = 地图边界 − 玩家半径/精灵半宽；背景网格铺满地图，边缘可见，无空气墙。
- **相机**：`LateUpdate` 指数平滑 `t = 1 - exp(-8×dt)`，x/y 各自钳制在地图内；
  重开时距离 > 8 直接 snap，避免长距离回拉。
- **出生**：以玩家为中心、半径 `1.15 × 相机半对角线` 随机取点；拒绝落在视野内（margin 0.05），最多重试 8 次；
  全失败退回视野外最远方向；出生点可以在地图外。
- **回收**：离开相机视野（±0.05）持续 3 秒 → `Unregister` + `Destroy`；**进过视野后才计时**，避免误杀刚出生的敌人。
- **拥挤**：`EnemyAI` 只 seek 到自己的站位点（12 槽、停距 ≈0.7、到达容差 0.25）；
  `EnemySpawner` 每帧 1～2 轮两两位置修正（间距 0.95）；**不再使用 1/d² steering 分离力**。
  残余：20 只超过单环容量时群体仍会缓慢绕圈；占位 sprite 视觉上仍有轻微交叠。
- **压力**：敌人速度 = 基础 × ±12% × `Lerp(1,1.15,elapsed/60)`，上限 2.2；
  作用于已存在敌人，避免“27 秒后没有新敌人就失效”。
- 依据：Brotato 的波次压力/站位、20MTD 的走位生存；实现是简化版，未做 Boss/远程/技能树。

## 6. UI / H5 外壳

### 6.1 Unity 内

- HUD：生命条 + 数字（左上）、剩余时间（上中）、暂停按钮（右上）、分数（暂停下方）。
- 手机窄屏（`Screen.width < 1000` 设备像素）切 `640×360` 参考分辨率，HUD/面板一起放大；否则 `1280×720`。
- 暂停面板：标题 + 3-2-1 + 「继续」；手动与失焦恢复都走 3-2-1。
- 结算：WebGL 嵌入模式隐藏 Unity `ResultPanel`，由 H5 卡片统一展示；Editor 保留 Unity 面板自测。
- 受击反馈：玩家红闪 + 10Hz 闪烁（`PlayerView`）。

### 6.2 H5

- 页面状态：`Loading → Ready → Starting → Playing ↔ Paused → Result`；按钮/文案由 Unity 状态事件驱动。
- 昵称：空 → 「玩家」；按码点截 16；纯文本渲染；保存到 localStorage（`survival.nickname`）。
- 最高分：`survival.bestScore`；`newScore > best` 才更新；刷新仍在；不可用时内存回退并提示。
- 开始按钮：`onReady` 前禁用；`SendMessage` 是同步的，**先设页面状态再发指令**（顺序不能反）。
- 结算卡片：本次得分 / 最高分 / 昵称 / 存活秒数 / 新纪录；`scrollIntoView({block:'start'})` 保证首屏可见。
- 加载：进度百分比；失败显示错误卡片 + 重试；`file://` 明确提示需要 HTTP 服务。
- 移动端：`touch-action:none`、安全区 `env(safe-area-inset-*)`、竖屏提示「横屏体验更佳」、DPR ≤ 2。
- **H5 全屏（M4.5 §1，已实现）**：`#btn-fullscreen` 只在 Playing/Paused 显示；全屏用 `html:fullscreen` 隐藏
  页头/页脚/操作提示/竖屏提示/结算卡，游戏区按 16:9 letterbox 居中、背景纯黑；右下角固定「退出全屏」按钮。
  全屏中死亡自动退出全屏再显示结算；`requestFullscreen` 被拒（如 iPhone Safari）提示「当前浏览器不支持网页全屏，
  请横屏或添加到主屏幕」；`screen.orientation.lock('landscape')` 为 best-effort。
- 未实现：暂停菜单“重新开始”（M4.6 P1）、主菜单/难度（M4.5 §3）、音效。
- 依据：CrazyGames/Poki 的 `gameplayStart/Stop` 生命周期、浏览器 visibility 规范、WebGL 外壳的 return state；见 §10。

## 7. 桥接协议摘要

- 加载：`createUnityInstance(canvas, config, onProgress)`，**不用 iframe**；失败走错误卡片。
- H5 → Unity：`SendMessage('WebGLBridge', method, jsonString)`；一次只能一个 string。
- 方法：`StartGame`、`PauseGame`、`ResumeGame`（只请求倒计时）、`RestartGame`、`SetPausedByVisibility`。
- Unity → H5：`onReady`、`onStateChange`（状态字符串）、`onGameOver`（分数/存活/击杀/昵称/明细）。
- JSON 全部 `JsonUtility.ToJson` 生成；`onGameOver` 每局一次（`_reported` 守卫）。
- 协议版本 **1**；无新增方法/字段时保持不变。细节与时序图见 `docs/bridge-protocol.md`。

## 8. 构建 / 性能 / WebGL 约束

### 8.1 构建

- Unity `6000.3.22f1`，Built-in Render Pipeline，WebGL2，IL2CPP。
- 压缩：Brotli + **Decompression Fallback**（静态服务器没配 header 也能跑）。
- 产物：`.unityweb` 后缀（`unity.data/framework/wasm.unityweb`）+ `unity.loader.js`；
  `build-info.json` 由 `BuildScript` 扫描生成，不手改。
- 构建耗时约 4 分钟；M4.6 构建 `2026-10-31T10:02:10Z`，wasm 7.00MB + data 2.45MB + framework/loader ≈ 9.3MB。
- 构建前自动重烤 TMP 中文字体图集 + 重建场景（`SceneSetup`）；场景不要手拖。
- 本地/线上版本号：**最终构建时把 H5 版本串（当前 `1.0.0`）与 `build-info.json` 的 `productVersion`（当前包里仍是 `0.1.0`）对齐**。

### 8.2 性能

- 桌面 Chrome 实测约 165 FPS（受 165Hz 屏限制，p95 帧间隔 6.2ms）；中端手机帧率**未测**。
- 同屏 ≤20；`Update` 无每帧 GC（Editor/E2E 观察）；`Time.maximumDeltaTime = 0.1f` 防切回尖峰。
- DPR 上限 2；手机窄屏 HUD 用 640×360 参考分辨率。
- 官方依据：
  - Unity Web 性能：GPU 接近原生；WebGL 调用有 CPU 开销，**减少 draw call、用 batching/instancing**；
    后台标签页多数浏览器约 1 次/秒更新，`Time.maximumDeltaTime` 默认小于 1 秒会让 `Time.time` 变慢。
  - Unity Web 内存：Unity heap 是连续内存块，自动扩容可能因无法分配连续块而崩溃，**尽量保持 heap 小**；
    移动端浏览器建议调 `Memory Growth Mode` / Initial Memory Size。
  - `Time.maximumDeltaTime`：限制慢帧后的 `Time.deltaTime`，避免瞬移；最小等于 `fixedDeltaTime`。
- **未做**：stripping / 关闭 Decompression Fallback / 包体优化（M5 评估，先实测再改）。
