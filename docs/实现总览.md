## 2. 玩法规则与数值

### 2.1 计分

```
存活分 = 已存活整数秒 × 10 × 难度倍率   // 简单 1.0 / 普通 1.3 / 困难 1.6
击杀分 = 击杀数 × 20        // 当前没有攻击手段，Kills 恒为 0，接口保留
胜利奖励 = 200（仅胜利）    // 不乘难度倍率
最终分 = 存活分 + 击杀分 + 胜利奖励
```

- 60 秒胜利、无击杀时：简单 `600+200=800`、普通 `780+200=980`、困难 `960+200=1160`。
- 倍率在开局时取自 `DifficultyProfile.ScoreMultiplier`；一局内不变。
- **M6 §5 的计分改造（0.1 秒粒度、分段加速、血量分）尚未实现**，当前仍是整数秒 × 10。
- 剩余时间显示 `回合时长 - 已存活秒数`，向上取整；格式 `mm:ss`（60 秒：开局 `01:00`、结束 `00:00`；
  压测把回合拉长到 600 秒时显示 `09:35` 这类正常进位，2026-11-01 修）。

### 2.2 数值（以 `GameConfig` / `EnemyDefinition` 为准）

## 3. 状态机与暂停/恢复

### 3.1 状态

```
Booting ──初始化──▶ Menu ──菜单开始──▶ Starting(3s) ──▶ Playing
Paused ──继续──▶ Starting(3s) ──▶ Playing（不重置）
Paused ──重新开始──▶ Starting(3s) ──▶ Playing（倒计时结束才 ResetRound）
Result ──再来一局──▶ Starting(3s) ──▶ Playing（同档，倒计时结束才 ResetRound）
Playing ⇄ Paused（暂停按钮 / Esc / P / 失焦）
Playing ──HP≤0 / 60s──▶ Result（发 onGameOver 一次）
Starting ──失焦取消──▶ 回来源态（Menu / Paused / Result）
Paused/Result ──返回菜单──▶ Menu（中止本局：StopSpawning + ResetRound，不结算、不发 onGameOver）
```

- 只有 `GameManager` 能改状态；`Time.timeScale = 0` 用于 Starting/Paused/Result，`ResetRound` 先恢复 1。
- `Starting` 是内部过渡态：只跑 unscaled 3-2-1，不发 `onStateChange`，不发 H5 文案；取消回来源态时
  timeScale 复位（Menu=1，Paused/Result=0）。
- 玩法逻辑用 `Time.deltaTime`；暂停/结算/倒计时冻结。UI 用 uGUI，不受 timeScale 影响。
- 重开不走 `SceneManager.LoadScene`，`RestartGame()` 在倒计时结束后重置分数/时间/HP/敌人/生成计时/相机。
- 菜单不显示最高分/昵称/全屏；难度只在菜单选，暂停重开/再来一局/返回菜单沿用当前档。
- `ReturnToMenu` 在 Menu 下幂等；Starting 中调用会先取消倒计时再回 Menu。
- 测试/压测专用 `StartGameImmediate` 绕过 3-2-1（仅 `PerfProbe ?perf=1&autostart=1` 使用）。

### 3.2 暂停/恢复（M4.6 语义）

| 场景 | 行为 |
|---|---|
| 手动暂停（按钮 / Esc / P） | Playing → Paused，`timeScale=0` |
| 窗口失焦 / 标签页隐藏 / 切 App | Playing → Paused；**切回仍保持 Paused**，不自动继续（Unity `OnApplicationFocus`；旧 H5 的 `SetPausedByVisibility` 兜底，幂等） |
| 玩家点「继续」/ 按 P 或 Esc | **先 3-2-1（`unscaledDeltaTime`），结束才 Playing**；手机用来把手指挪回屏幕 |
| 菜单开始 / 暂停重开 / 再来一局 | 同样先 3-2-1，结束才 ResetRound + Playing |
| 倒计时中重复按 P/Esc | 忽略（不加速、不取消） |
| 倒计时中失焦 | 取消倒计时回来源态（Menu/Paused/Result），切回不自动继续 |
| 失焦时处于 Menu/Result | 不误触发暂停 |

- H5 侧监听 `blur` / `focus` / `visibilitychange`，按最后发送值去重；失焦发 `"true"`，切回发 `"false"`。
- `SetPausedByVisibility("false")` **直接忽略**（H5 自己按最后发送值去重）；不请求倒计时、不恢复。
- 依据：网页游戏通行的“return state”（回到页面必须用户手势恢复），见 §10；3-2-1 是本作针对手机手位的刻意差异。

## 4. 输入

- **键盘**：WASD / 方向键；`PlayerInputSource` 抽象，`PlayerInputRouter` 在有触控时优先触控。
- **触控（手机）**：锚点相对拖动 + 外圈/摇杆头可视化（M4.7 只加视觉，不改输入算法）
  - 手指按下点 = 摇杆中心；`Move = clamp((current-anchor)/maxRadius, 1)`；
  - `maxRadius = clamp(Screen.height × 0.2, 80, 160)` 设备像素；死区 8px；松手归零；
  - 只跟踪第一根手指，记录 `fingerId`；换手指重新锚定；
  - 鼠标按住拖动走同一逻辑（Editor/桌面兼容）。
- **摇杆可视化（M4.7）**：按下时显示外圈 + 摇杆头，松手/暂停/离开 Playing 隐藏；只加视觉，不改上面的算法；
  桌面鼠标不显示。可视半径 = **min(Canvas 短边) × 0.07**（随视口等比，0.06～0.08 可调）；**外圈不是满速边界**。
- **暂停快捷键**：桌面 `Esc` / `P`；全屏时 Esc 可能被浏览器用于退出全屏，所以 P 必须可用。
- 依据：同类手机游戏普遍使用浮动/可见摇杆（Brotato 手机版、20 Minutes Till Dawn 移动版）；本作先保证手感与实现风险，再补视觉。

## 5. 地图 / 相机 / 敌人

- **地图**：36×20；玩家边界 = 地图边界 − 玩家半径/精灵半宽；背景网格铺满地图，边缘可见，无空气墙。
- **相机**：`LateUpdate` 指数平滑 `t = 1 - exp(-8×dt)`，x/y 各自钳制在地图内；
  重开时距离 > 8 直接 snap，避免长距离回拉。
- **出生**：以玩家为中心、半径 `1.15 × 相机半对角线` 随机取点；拒绝落在视野内（margin 0.05），最多重试 8 次；
  全失败退回视野外最远方向；出生点可以在地图外。
- **回收**：离开相机视野（±0.05）持续 3 秒 → `Unregister` + `Destroy`；**进过视野后才计时**，避免误杀刚出生的敌人。
- **拥挤（M6 2026-11-01 重做，替代钉子版）**：删除站位槽/分环/钉子逻辑，敌人只 seek「玩家 + 停距 0.70」，
  后排自然贴在前排背后（不再"到位即钉住"）；**软墙**只扣除朝邻居的逼近速度——R=0.90 开始线性减速、Dsoft=0.70
  完全停住，允许约 25～30% 精灵重叠，贴住后**不产生外推**、没有弹力。邻居用均匀网格 30Hz 刷新（cell 0.90、
  ≤8 个），移动 60Hz + 16/s 速度平滑，唯一 position 写入是 `pos += v*dt`（无两两位置修正）。
  被挡住/被顶住时切向让位（前 0.35 / 后 0.2 u/s），让正面排队变成侧向换位；玩家穿人群时敌人侧闪，
  玩家不受力、不被挡、可穿过。中心距 <0.5 的防重合兜底用连续加速（3.6 u/s²，总速 ≤2.64，仍低于玩家 3.2）；
  离屏生成点与现有敌人 <0.45 则重试。接触伤害仍走 Trigger（玩家穿过敌人只掉血）。
  占位 sprite 视觉上仍有轻微交叠（素材问题，未改）。验收见 `docs/tickets/M6-内容扩展.md §11.1`。
- **压力**：敌人速度 = 基础 × ±12% × `Lerp(1,1.15,elapsed/60)`，上限 2.2；
  作用于已存在敌人，避免“27 秒后没有新敌人就失效”。
- 依据：Brotato 的波次压力/站位、20MTD 的走位生存；实现是简化版，未做 Boss/远程/技能树。

## 6. UI / H5 外壳

### 6.1 Unity 内

- HUD：生命条 + 数字（左上）、剩余时间（上中）、暂停按钮（右上）、分数（暂停下方）；Menu/Result 隐藏。
- 手机窄屏（`Screen.width < 1000` 设备像素）切 `640×360` 参考分辨率，HUD/面板一起放大；否则 `1280×720`。
- **主菜单**：不透明底 + 标题「生存挑战」+ 副标题 + 三档难度卡（简单/普通/困难，显示倍率）+「开始游戏」；
  选中卡紫色；不显示最高分/昵称/全屏。
- **暂停菜单**：标题「已暂停」+ 竖排「继续 / 重新开始 / 返回菜单」；结算两按钮仍横排。
- **统一 3-2-1**：菜单开始、暂停继续、暂停重开、结算再来一局共用 `StartCountdownPanel`（遮罩 + 大数字）。
- **结算**：始终显示（WebGL 也不再隐藏）；标题（胜利/失败）+ 本局得分 + 难度/存活/倍率 +「再来一局 / 返回菜单」；
  不显示昵称与分数明细。
- 受击反馈：玩家红闪 + 10Hz 闪烁（`PlayerView`）。

### 6.2 H5 薄壳（v1.2）

- 页面状态：`Loading → Shell → Entered → GameOver`（`Error` 兜底）；`onStateChange` 只更新文案，不控制布局。
- 布局：**画布在上、昵称/成绩卡在下**（桌面与手机同一顺序）；画布 16:9；页面允许纵向滚动、无横向。
  昵称输入 Shell 可编辑、Entered 后只读；H5 不提供难度选择 UI。
- 进入：`onReady` 前开始禁用；点「开始游戏」只发一次 `EnterGame{nickname,lastDifficulty}`（先设 Entered 再发）。
  `onReady.protocol !== 3` → 禁用开始 + 错误卡「版本不匹配，请刷新重试」；状态事件早于 onReady 时直接进 Entered。
- 数据面板：单一最高分 `survival.bestScore`（旧三档键只读一次迁移，标记 `survival.bestScoreMigrated`）；
  最近一局只在内存；昵称 `survival.nickname`；难度偏好 `survival.difficulty` 由 `onDifficultyChanged` 代存、EnterGame 回传。
- 结算：Unity 画布内显示；H5 只更新数据面板，不弹 H5 结算卡。
- 全屏：入口只在 Entered 后出现；全屏元素只含画布，全屏内 0 个可点网页控件；toast 纯文字 2.5s；退出靠 Esc/手势；
  `requestFullscreen` 被拒（iPhone Safari）提示降级。
- 移动端：`touch-action:none`、安全区、竖屏提示「横屏体验更佳」；操作提示按 `pointer: coarse` 切触屏文案。
- 画布滚轮：Unity 运行时 preventDefault，H5 在 document 捕获阶段接管并 `scrollBy`（全屏/Ctrl 放行）。
- Shell 遮罩文案：「游戏已就绪 · 点击下方「开始游戏」进入」；版本 `?v=1.2.1` 5 处，`tools/check-version.mjs` 对比 `build-info.productVersion`。
- 旧 v1.1 H5 控件（难度卡/3-2-1/暂停/结算卡/分档最高分）已删除；旧脚本在 `tools/e2e/legacy/` 只供追溯。
- 依据：CrazyGames/Poki 的页面生命周期、浏览器 visibility/fullscreen 规范、WebGL 外壳 return state；见 §10。

## 7. 桥接协议摘要

- 加载：`createUnityInstance(canvas, config, onProgress)`，**不用 iframe**；失败走错误卡片。
- H5 → Unity：`SendMessage('WebGLBridge', method, jsonString)`；一次只能一个 string。
- 方法：`EnterGame`（`{"nickname","lastDifficulty"}`；未开局前进入，难度只作菜单初始选中）、
  `SetPausedByVisibility`（旧页失焦兜底）；旧 `StartGame` 按 `EnterGame` 兼容，旧局内指令为 no-op。
- Unity → H5：`onReady`（protocol 3 + capabilities）、`onStateChange`（`menu/playing/paused/result`）、
  `onDifficultyChanged`（菜单选择变化，H5 代存）、`onGameOver`（分数/存活/击杀/昵称/难度，字段沿用 v2）。
- JSON 全部 `JsonUtility.ToJson` 生成；`onGameOver` 每局一次（`_reported` 守卫）。
- 协议版本 **3**；细节与时序图见 `docs/bridge-protocol.md`。

## 8. 构建 / 性能 / WebGL 约束

### 8.1 构建

- Unity `6000.3.22f1`，Built-in Render Pipeline，WebGL2，IL2CPP。
- 压缩：Brotli + **Decompression Fallback**（静态服务器没配 header 也能跑）。
- 产物：`.unityweb` 后缀（`unity.data/framework/wasm.unityweb`）+ `unity.loader.js`；
  `build-info.json` 由 `BuildScript` 扫描生成，不手改。
- 构建耗时约 3:42；v1.2 最终构建 `2026-11-02T13:05:32Z`（productVersion **1.2.1**），总 9,651,481 B
  （wasm 7,002,319 / data 2,435,710 / framework 75,669 / loader 117,894），已入库 `web/unity`。

### 8.2 性能

- 桌面 Chrome 实测约 165 FPS（受 165Hz 屏限制，p95 帧间隔 6.2ms）；中端手机帧率**未测**。
- 同屏 ≤20；`Update` 无每帧 GC（Editor/E2E 观察）；`Time.maximumDeltaTime = 0.1f` 防切回尖峰。
- DPR 上限 2；手机窄屏 HUD 用 640×360 参考分辨率。
- 官方依据：
  - Unity Web 性能：GPU 接近原生；WebGL 调用有 CPU 开销，**减少 draw call、用 batching/instancing**；
    后台标签页多数浏览器约 1 次/秒更新，`Time.maximumDeltaTime` 默认小于 1 秒会让 `Time.time` 变慢。
  - Unity Web 内存：Unity heap 是连续内存块，自动扩容可能因无法分配连续块而崩溃，**尽量保持 heap 小**；
    移动端浏览器建议调 `Memory Growth Mode` / Initial Memory Size。
  - `Time.maximumDeltaTime`：限制慢帧后的 `Time.deltaTime`，避免瞬移；最小等于 `fixedDeltaTime`。
- **未做**：stripping / 关闭 Decompression Fallback / 包体优化（M5 评估，先实测再改）。
