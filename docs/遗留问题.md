# 遗留问题（执行前先看）

> 每次开始新里程碑（M2/M3/…）前先读本文件；解决一条就删一条。

## 1. 输入后端已改为 Both（M1）

- `ProjectSettings/ProjectSettings.asset`：`activeInputHandler = 2`（Both）。
- 原因：模板默认只启用新 Input System，而规范 5.5 要求用内置 `Input`（`Input.GetAxisRaw`）。
- 影响：改动需要重启 Unity 编辑器才生效；新 Input System 仍可用。

## 2. WebGL 构建产物入库（M5 起）

- `web/unity/` **随仓库入库**（M5 交付起，见 `.gitignore` 构建产物段注释与 `docs/M5-执行记录.md`）；
  重建后在**同一次 `build:` 提交**里更新源码与产物，不要只改源码不更新产物。
- `build-info.json` 由 `BuildScript` 扫描生成，不要手改；版本口径以最终构建的 `productVersion` 为准。
- v1.2 清理期间允许把 1.2.0 临时复制进 `web/unity` 跑测试，结束后 `jj restore web/unity`，
  等最终构建再单独入库（不要让 wip 背 9.3MB 半版本）。

## 3. SceneSetup 的已知坑

- `EditorSceneManager.NewScene` 会卸载未被场景引用的资源（`GameConfig` 曾被判为未使用而变成空引用）。
- 现状：`NewScene` 之后重新 `LoadAssetAtPath` 再赋值（GameConfig / Sprite / TMP Font Asset 都要重取），已在 `Assets/Editor/SceneSetup.cs` 注释说明；改 SceneSetup 时不要把这个重载删掉。
- 现在 `BuildScript` 每次构建前都会调用 `SceneSetup.GenerateScene()`，场景永远由代码生成，不要手工在场景里改结构。

## 4. 编辑器失焦时 Play 循环会停（本机实测）

- Player Settings 的 **Run In Background = 关闭**（规范 11.1 要求），Unity 编辑器在窗口失焦时会把 Play 循环一起停掉：表现为 `Time.frameCount` 停在 1~2、`Time.time` 不涨、Console 里只剩 `[GameManager] state=Playing`。
- 自测时趁 Play 中执行一次 `Application.runInBackground = true`（只改运行期，不动 PlayerSettings）即可恢复；这不是代码 bug。
- 排查时先看这条，别误判成玩法卡死。

## 5. TMP 中文文案与字体图集

- 游戏内文案全部在 `Assets/Scripts/UI/UiStrings.cs`；字符集在 `Assets/Fonts/ui-chars.txt`。
- 字体资产 `Assets/Fonts/NotoSansSC-UI-SDF.asset` 由 `Assets/Editor/FontAssetBuilder.cs` **用脚本生成**（菜单 `Survival/Rebuild Font Asset`）：
  - `Survival/Setup Scene` 缺字体时自动生成
  - `Survival/Build WebGL` 构建前无条件重烤
- 新增文案时：改 `UiStrings`（或 `ui-chars.txt`）→ 构建即可。若新字不在 `NotoSansSC-UI-Subset.otf` 子集里，构建会直接报错并列出缺字，此时需要完整字体（`NotoSansSC-Regular.otf`，OFL）重新裁子集：
  `python tools/font-subset.py --source <完整字体> --chars Assets/Fonts/ui-chars.txt --output Assets/Fonts/NotoSansSC-UI-Subset.otf`
  （v1.2 清理后按 `UiStrings.AllCharacters` 重裁到 71 字符；完整字体 8.3MB 不入库）。
  1024 图集上限约 144 glyph，扩字前先算容量，放不下先停报。

  **该接口保留，不在 v1.2 清理中删除**（后续加攻击手段时直接调用；见 `docs/代码审视-2026-11-02.md` §3.1）。

  iPhone Safari / Android Chrome 真机仍待 M4 门禁（见 `docs/测试计划.md`）。
- **Honor 90 Pro（Android Chrome）线上加载失败（2026-10-31，用户实测）**：打开线上 URL 基本加载不出来。
  同日在本机**直连**（不走代理）测 Netlify：`index.html` 200 / 1.4s，但 `unity.wasm.unityweb` 只有约 **31KB/s**，
  2MB 跑满 60s 仍未下完；9.3MB 首包推算约 5 分钟，手机侧大概率更差。
  **初步判断是境外 CDN 带宽问题，不是 WebGL/设备问题**；待验证：手机与 PC 同一 Wi-Fi 访问本地静态服务
  `http://192.168.1.100:8000`（PC 上已有服务），能秒开即确认。修复方向是国内托管（`docs/部署与托管.md`，M5 决策），
  M4 不改构建参数。
- **M4.6 暂停/恢复语义（2026-10-31）**：失焦只暂停并保持，玩家点「继续」/按 Esc/P 才 3-2-1 后恢复；
  倒计时中重复按 P 忽略。残余：倒计时中再次失焦停表只做了代码路径核对（E2E 未单跑）；
  按住方向键失焦、在别处松开的残留输入未复现测试，真机阶段观察；M4.6 P1（暂停菜单「重新开始」、输入复位）未做。
- **DPR 上限 2 已配置**：`web/js/bridge.js` 给 `createUnityInstance` 传 `devicePixelRatio: min(dpr, 2)`；
  HUD 缩放阈值用 `Screen.width`（设备像素）判断，依赖这个比例。真机是否掉帧仍待实测（中端 Android <30 FPS 时降到 1.5）。
- **加载性能**：WebGL 产物约 9.3MB（wasm 6.97MB + data 2.45MB），走代理时 Netlify 实测约 165KB/s、首次加载 50～61s；
  **本机直连仅约 31KB/s**（2026-10-31 实测），9.3MB 推算约 5 分钟，这解释了 Honor 90 Pro 打不开。
  M4 优先评估国内托管，M4/M5 评估 stripping / 缓存；详见 `docs/tickets/M4.md` 第 1.6 节。
- **可选的 `RequestState` 一次性查询**：H5 点开始后若状态回调丢失，目前只能提示刷新。
  需要 Unity 侧新增方法并重建包；M4 测试若复现回调丢失再加，不要为它单独重建。
- **`unityInstance.SendMessage` 是同步的**：`onStateChange` 可能在 `SendMessage` 返回前就回调到页面。
  写 H5 交互时必须「先设置页面状态/兜底计时器，再发送指令」，并让状态回调负责取消兜底；
  反过来（先发后设）会把刚到的状态覆盖掉。`web/js/app.js` 的 `startGame` 已按此顺序实现，改 H5 时别改回去。
- `Assets/Fonts/NotoSansSC-UI-Subset-SDF.asset` 是切 TMP 时手工生成的一份遗留字体资产，代码已改用 `NotoSansSC-UI-SDF.asset`；确认无引用后应删除（还没删，见 M2 记录）。
- 无头/软件渲染的 Playwright 环境里 Unity 帧率极低（`Time.maximumDeltaTime = 0.1` 导致游戏时间约慢 10 倍），浏览器全程自测会偏慢；这是测试环境现象，不是玩法 bug。
- **E2E 的失焦测试**：Playwright 默认开启焦点模拟（`document.hasFocus()` 恒 true、blur 不触发），
  `tools/e2e/smoke.mjs` 用 CDP `Emulation.setFocusEmulationEnabled(false)` 关掉后再开第二个浏览器窗口制造真实 blur；
  Firefox 没有这个开关，失焦用例只在 Chrome/Edge 跑。
- **Unity Test Framework 的 PerformanceTestRun 资源**：进入 Play 时会在 `Assets/Resources/` 生成
  `PerformanceTestRunInfo.json` / `PerformanceTestRunSettings.json`（MCP 测试包行为），会随构建进包；
  确认无引用后可以删，不要把它们当成项目资源提交。

  旧页不认识 `menu/playing/...` 小写状态，页面文案可能停在旧状态，且 Unity 结算与旧页结算卡会双显。
  同版本部署 + `?v=1.2.0`，H5 薄壳改版后消除。
