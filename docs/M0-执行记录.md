## 四、偏差与决策

1. **`EditorApplication.Exit` 只在 batchmode 调用**
   ticket 要求成功/失败都 `Exit(code)`，但那会让菜单构建顺手关掉编辑器。实现为 `if (Application.isBatchMode) EditorApplication.Exit(code)`；菜单构建失败只 `LogError`，编辑器保留。

2. **产物是 `.unityweb` 而不是 `.data.br`**
   本机 Unity 6 + Brotli + `decompressionFallback = true` 产出 `.data.unityweb` / `.framework.js.unityweb` / `.wasm.unityweb`。
   因此扫描规则是「先精确后缀，再匹配带压缩后缀的变体」，不硬编码文件名；换 Unity 版本重跑构建即可自适应。
   静态服务器无需配置 `Content-Encoding`，由 Unity 的 JS 解压兜底。

3. **Unity 路径修正**
   `CLAUDE.md` 原路径错误，已按 revisionHash 核对后改为 `D:\unity hub\Editor\Unity.exe`。

4. **MCP 端口修正**
   `CLAUDE.md` 原写 8080，本项目实际为 8081，已改正。

## 六、遗留问题

1. **Playwright MCP 已从 `--extension` 改为 Chrome channel（已解决，重启后已验证生效）**
   - 原配置 `--extension` 只连接「已打开且已配对」的 Chrome/Edge，Chrome 未运行时会无限等待；本机 `%LOCALAPPDATA%\ms-playwright` 也没有浏览器内核，无法退回内置 Chromium。
   - 现配置为 `--browser chrome`（使用本机已安装 Chrome，无需下载内核，备份 `~/.claude.json.bak-m0`）。
   - 重启后实测：`browser_navigate` → `browser_wait_for("Unity Ready")` → 点击按钮 → 读到 `Pong: hello-from-h5`，Console 0 error，MCP 工具可正常使用。

2. **`/favicon.ico` 404 已消除**
   浏览器自动请求 favicon 会在 Console 留下一条 404。`web/index.html` 已加 `<link rel="icon" href="data:,">`，复测 Console 错误数为 0。

3. **首次加载体积**
   当前构建 8 MB（未压缩传输），在规范预算 15 MB 以内。若后续内容变多，可评估关闭 Decompression Fallback + 服务器配 `Content-Encoding`。

4. **`web/unity/index.html` 与 `TemplateData/` 是 Unity 默认产物**
   我们的外壳不用它，保留作兜底预览；不需要时可让 `BuildScript` 清理。
