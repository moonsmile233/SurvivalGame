# 参考拆解：同类游戏与 Web-Unity 外壳

> 文档版本：2026-10-31T18:45+08 · 作者：策划 · 改前必须从磁盘重读；上下文旧副本作废。
> 目的：做新玩法 / 新 UI / 新流程前，先拆同类作品怎么做，再映射到作业要求；不要只用"需求没写"当不做的理由。

## 1. 为什么要做这份拆解

这次 M0–M4 的入口流程是"H5 昵称 + 开始按钮 → Unity 直接 Playing"。它满足作业，但漏掉了同类产品的常见结构：

- 游戏内主菜单（难度、继续、开始）
- 暂停菜单（继续 / 重新开始 / 退出）
- 全屏按钮
- 手机横屏 / 安全区 / 页面沉浸

这些不是凭空想的，而是 Brotato 和大量 Unity WebGL 游戏的标准做法。以后新项目/新阶段先做这份拆解，再定功能。

### 1.1 参考源按“设计对象”换，不要一两个游戏包打天下（2026-10-31 用户要求）

| 设计对象 | 该参考什么 | 不该拿什么当依据 |
|---|---|---|
| 玩法 / 数值 / 敌人 AI / 关卡节奏 | 同品类游戏（2D survivor-like：Brotato、Vampire Survivors、20 Minutes Till Dawn） | 网页外壳、后台系统 |
| 网页交互 / 入口 / 菜单 / 暂停 / 全屏 / 触控 / 加载 | Web/WebGL 游戏外壳与平台（CrazyGames/Poki/itch.io、HTML5 游戏实践、浏览器 API 规范） | 只参考单机游戏客户端 |
| 性能（帧率 / GC / 内存 / 包体 / WebGL 限制） | 引擎官方文档 + 行业工程实践（Unity/浏览器性能指南） | “某款游戏就是这么做的” |
| 后端 / 网络 / 部署 / 缓存 / CDN | 行业技术资料、云厂商文档；必要时看同类产品公开架构 | 游戏 UI 习惯 |

## 2. 同类作品拆解

### 2.1 土豆兄弟（Brotato，手机/PC）

- **入口**：主菜单选角色/难度 → 开始 → 进入一局；局内是波次 + 波间商店。
- **暂停**：局内可暂停，暂停菜单是完整界面（继续/退出），不是只有一颗按钮。
- **难度**：开局前选择，影响敌人强度/数量，而不是局中临时调。
- **存档/继续**：属于 run-based 游戏；同类作品通常按"波次/节点"保存，而不是随时存。
- **对我们的启示**：主菜单/难度/暂停菜单是"游戏的一部分"，不是网页外壳的附属；但我们是 60 秒单局，不需要波间商店和复杂存档。

### 2.2 Unity WebGL + H5 外壳（itch.io / CrazyGames / Poki 类）

- **H5 负责**：加载进度、昵称/账号、开始、全屏、音量、排行榜、错误重试、移动端提示。
- **Unity 负责**：玩法、状态机、暂停、关卡、结算数据。
- **全屏**：几乎都有；桌面/Android 用 `requestFullscreen`，iOS Safari 对任意元素全屏支持有限，通常给"横屏/添加到主屏幕"提示。
- **入口**：H5 的"开始"通常进入游戏内主菜单或直接开局；大型作品会先在 Unity 内显示主菜单。
- **对我们的启示**：H5 的开始按钮是外壳职责（作业也明确要求），但 Unity 内可以再有一层主菜单；全屏按钮应放在 H5。

### 2.3 其他 H5 小游戏外壳

- 常见元素：开始页、难度、操作说明、设置（音量/画质）、暂停、结算、再来一局、全屏、分享。
- 移动端：横屏提示、安全区、触控区、防止页面滚动/缩放。
- 加载：进度条 + 失败重试；首次加载体积大时给出预期。

### 2.4 暂停 / 恢复（2026-10-31 补查，用户真机反馈触发）

| 作品/平台 | 暂停 | 恢复 | 失焦/切后台 |
|---|---|---|---|
| **Brotato**（PC/移动） | 即时，随时可停 | **即时**，无倒计时 | 切后台暂停；移动版可随时中断/继续（自动存档） |
| **20 Minutes Till Dawn** | 有暂停键/菜单 | **即时**；移动版后补 mid-run save | 切后台暂停 |
| **Vampire Survivors** | 暂停菜单 | 即时 | PC 窗口失焦行为不稳定（Electron 后台节流）；移动版有切后台丢局/灰屏反馈，属于反面案例 |
| **通用引擎/平台模式**（cocos2d、Unity 教程、GameNative、Eden） | 切后台立即暂停 | **回到前台保持暂停，显示 Resume 按钮，玩家点了才继续** | 不自动 resume；手动暂停不得被休眠/唤醒覆盖 |
| **恢复 3-2-1 倒计时** | 个别游戏有（如 Apotris 做成开关） | 不是 Survivor-like 标配；更多用于**开局/开波** | — |

**结论**：

- 这个品类的主流是 **暂停即时、恢复即时、失焦保持暂停**，恢复动作永远由玩家触发。
- 我们此前的「失焦 → 自动 3-2-1 → 自动继续」是反的：最该由玩家决定的路径反而自动执行；
  手动继续却是即时。用户真机反馈「暂停后没有 3 秒倒计时」正是这个不一致暴露出来的。
- 修订为：**失焦 = 暂停并保持；玩家点继续/按 P 后先走 3-2-1，再恢复**。
  - 3-2-1 保留，但**只由玩家主动恢复触发**；自动恢复路径删除。
  - 这是本作的刻意选择（移动端需要时间把手指移回屏幕），不是行业标配；写进文档，避免后续被“优化”掉。

### 2.5 网页 / WebGL 外壳的通用做法（2026-10-31 补查）

| 做法 | 说明 | 对本作 |
|---|---|---|
| `visibilitychange` → 暂停 | 不要只靠 rAF 被浏览器节流；显式进入 Paused | 已做，另有 `blur/focus` |
| 回到页面**保持暂停** | 显示 Resume 覆盖层/按钮，玩家点一下才继续；不要自动 resume | 改为本方案 |
| 恢复必须是用户手势 | 浏览器音频、全屏、指针锁都要求手势；恢复游戏也按这个心智模型 | 暂停面板按钮/P 键 |
| 重置帧时间基准 | 后台期间累积的 delta 会让首帧“瞬移”；恢复时清基线或夹住 delta | `Time.maximumDeltaTime=0.1`；倒计时 `MaxCountdownStep=0.1`；验收长时间切后台 |
| 清理按住输入 | 失焦时按住的键在别处松开，keyup 丢失会残留；触摸锚点也可能残留 | M4.6 §1.3 先测，再决定是否 `ResetState` |
| 保留手动暂停 | 用户主动暂停后切走，visibility 事件不应把它自动恢复 | 现有 `_pausedByVisibility` 标记；新方案下更安全 |
| 平台 SDK 生命周期 | CrazyGames/Poki 用 `gameplayStart/Stop` 包住暂停/恢复；没有内置 visibility 回调，仍要自己监听 | 本作不接 SDK，仅作外壳参考 |
| 全屏 / 横屏 | `requestFullscreen` 必须用户手势；iOS Safari 限制多；横屏提示/全屏按钮放 H5 | M4.5 §1 |

### 2.6 内容扩展参考（2026-11-01，主界面 / 多敌人 / 难度 / 计分）

> 触发：2026-11-01 用户决定交付后继续加内容。方法按 §1.1：玩法看同类游戏、入口看平台规范、性能看引擎文档。
> 对应设计见 `docs/tickets/M6-内容扩展.md`。

**主界面 / 入口**

- **CrazyGames 质量/玩法规范**：新玩家应尽快进入游戏；做不到时**最多 1 次点击**；引导放在游戏内、可跳过；
  按钮文案明确、不能人为拖延；全屏由平台提供（平台托管时禁止自建全屏按钮）。
- **HTML5 游戏菜单的两种实现**：游戏内状态（自带资源生命周期）vs DOM/CSS 覆盖层（更轻、复用网页排版）。
- **Brotato 流程**：主菜单 → 选角色 → 选武器 → 选难度 → 开局；难度开局前定、局中不可改。
- 结论：本作是 H5 外壳 + 60 秒单局，**入口只保留 H5 一层**（昵称 / 难度 / 开始），不叠第二个 Unity 主菜单
  （两层菜单 = 2 次点击，违反“最多 1 次点击”的通行标准）；难度在开始前选，局内只有暂停/结算。

**多种敌人**

- **Brotato**：敌人按角色分工——直冲、冲锋（约 2.5～3.5s 冷却冲刺）、远程/风筝（靠近就后退并远程打）、
  支援（加血/加攻/加移速）、召唤、资源/中立；按“首次出现波次”解锁，高难度提前解锁。
- **From The Downtown（USU 论文）**：chaser / charger / melee / ranged 四类 + FSM 驱动；
  无限波权重示例 melee 35% / chaser 25% / range 20% / charger 20%，按波次解锁。
- **b.mphilley《Enemy Designs》**：冲锋必须**有前摇、固定路径、激活后可躲**；每种敌人对应一种玩家技巧。
- 结论：只借「按角色分工 + 前摇可躲 + 按波次/时间解锁」这三点。做 3 类（追击 / 冲锋 / 绕行），每种只改**近身**移动与出手方式；
  **远程、召唤、支援、精英、Boss 一律不做**。用户 2026-11-01 重申的硬边界：**玩家没有任何攻击手段，敌人也没有远程手段**，
  伤害只能是接触/冲刺；上面 Brotato 的远程/支援/召唤只是拆解参考，不进入本项目。

**难度**

- **Brotato Danger 0–5**：累进修正；HP/伤害按档位给百分比（D3 +12%、D4 +26%、D5 +40%），
  新敌人随难度提前出现，精英/兽潮在 11–18 波插入；开局前选定，局中不变。
- **20 Minutes Till Dawn Darkness 0–15**：逐档叠加（生成频率 +25%、HP +25%、速度 +15%、伤害翻倍等），
  另有 Standard / Quickplay / Endless 三种模式。
- 结论：3 档（简单/普通/困难），只改 5 个乘区（速度、生成间隔、伤害、同屏上限、敌人解锁时间）+ 计分倍率；
  胜利条件三档都是 60 秒，避免“选简单才能通关”的验收歧义。

**计分**

- **Vampire Survivors 结算页**：分列展示存活时间、击杀、等级、金币等，不合成单一分数；排行榜由社区公式合成。
- **Brotato**：材料同时是 XP 与金币，波末结算，没有统一“分数”。
- **擦身/风险计分案例**：Jupiter Jump（贴近地雷给近失奖励并提升倍率）、Graze: Near Miss（贴边得分远高于正中）、
  One More Run（Perfect Dodge 大额奖励 + Risk Mode）、Cyber Dive（越靠近危险得分越高）。
- 结论：保留单一总分，构成 = **分段加速的存活分 + 剩余血量 + 难度倍率 + 胜利奖励**，结算页展示明细。
  - **擦身分不做**（用户 2026-11-01 决定）：擦身类案例（Jupiter Jump / Graze / Cyber Dive）证明“风险走位可计分”，
    但判定要写冷却、玩家也不一定理解为什么走得近反而加分；本作把收益放到“存活分段”和“剩余血量”上，更直白。
  - **存活分分段加速**（每 15 秒提一档每秒得分）而不是固定每秒 10 分：早死不吃亏、晚死明显更值钱，
    制造“再撑一会儿”的张力；实现上只是查表累加，不新增判定系统。

## 3. 作业要求 vs 同类标配

作业原文（逐字，节选 H5 部分）：

```text
输入玩家昵称；
开始游戏按钮；
嵌入 Unity WebGL 游戏；
游戏结束后，Unity 把分数传给 H5；
H5 显示本次成绩和历史最高分；
最高分使用 localStorage 保存；
页面适配电脑和手机宽度。
```

| 项 | 作业要求 | 同类标配 | 结论 |
|---|---|---|---|
| H5 昵称 + 开始按钮 | **必须** | 常见 | 保留在 H5，不能整体搬进 Unity |
| 游戏内主菜单（难度/继续/退出） | 未要求 | 常见 | 值得加；放在 H5 开始之后，由 Unity 显示 |
| 暂停菜单（继续/重开/退出） | "支持暂停" | 常见 | 现在是单按钮面板，应补成菜单（M4.6 P1） |
| **暂停/恢复语义** | "支持暂停" | **暂停即时、恢复即时；失焦保持暂停** | 当前是「失焦→自动 3-2-1 恢复」，反了；改为**切回保持暂停；玩家点继续/按 P 后 3-2-1 再恢复**（M4.6 P0） |
| 难度分级 | 未要求 | 常见 | 可选增强；3 档，影响敌人参数 |
| 保存并退出 / 继续 | 未要求 | run-based 常见 | 60 秒单局不建议做持久存档；做"局内继续/退出"即可 |
| 全屏按钮 | "页面适配宽度" | 常见 | 适配 ≠ 全屏；全屏是增强，值得加；iOS 有限制 |
| 键盘暂停 | 未要求 | 桌面常见 | 补 Esc/P（M4 §1.7） |

## 4. 建议的入口流程（两段式）

```text
H5: 昵称 + [开始游戏]（作业要求，保留）
  → Unity 主菜单：难度（简单/普通/困难）｜继续（局内）｜开始｜退出到网页
  → Playing
  → Paused：继续（点后 3-2-1）/ 重新开始 / 返回主菜单 / 退出到网页
      · 手动暂停与失焦暂停都停在这里；**切回不会自动继续**，玩家点继续/按 P 后先倒数 3 秒
  → Won/Lost：H5 结算卡（分数/最高分/新纪录）→ 再来一局（同难度）或返回主菜单
```

- **不把 H5 开始按钮删掉**：它承载昵称与"进入游戏"，也是作业明确要求。
- **Unity 主菜单** 才是难度/继续/退出发生的地方；需要新增 `Menu` 状态（或明确复用 `Ready`）并同步协议。
- **保存并退出**：60 秒单局，建议只做"暂停 → 退出到主菜单/网页"，不持久化局内状态；
  刷新后重开。真正的持久存档是另一个量级（序列化敌人/计时/随机器），不建议为作业做。
- **全屏**：H5 按钮；全屏时隐藏页头/页脚/提示，画布按 16:9 letterbox；`Esc` 会退出全屏，所以暂停用 `P` 兜底；
  iOS Safari 失败时提示"横屏或添加到主屏幕"。

> 这些是"同类标配"，但作业的硬门槛仍是 17 条 + 移动端 + 构建交付。**主菜单/难度不得挤占 M5 的必需交付**；
> 由用户决定是否在交付前做，做不完就停在当前可玩状态。
