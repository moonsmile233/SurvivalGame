## 2. `Assets/Editor/SceneSetup.cs`

菜单项：`Survival/Setup Scene`

行为：
1. 新建空场景，保存为 `Assets/Scenes/Game.unity`
2. 创建 `Main Camera`：正交投影，`orthographicSize = 5`，背景色 `#1E1E2E`，位置 `(0,0,-10)`
3. 创建空物体 `WebGLBridge`，挂 `WebGLBridge` 组件
4. 创建空物体 `Bootstrap`，挂 `GameBootstrap` 组件
5. 把 `Game.unity` 写入 `EditorBuildSettings.scenes`（仅保留这一个，enabled = true）
6. `Debug.Log` 输出场景绝对路径

同时提供静态方法 `GenerateScene()`，供 `-executeMethod SceneSetup.GenerateScene` 调用。

## 3. `Assets/Scripts/Core/GameBootstrap.cs`

M0 版本只做三件事：

1. `Start()` 里等一帧（`yield return null`）后调用 `WebGLBridge.NotifyReady()`
2. `OnGUI()` 在屏幕左上角显示 `Unity Ready`（英文，字号 24，白色）
3. 收到 Ping 后，在下方显示 `Pong: <消息内容>`

不要用 UGUI/TextMeshPro，M0 用 `OnGUI` 即可，M1 再替换。

## 4. `Assets/Scripts/Bridge/WebGLBridge.cs` + `WebGLBridge.jslib`

必须挂在名为 `WebGLBridge` 的 GameObject 上（`SendMessage` 靠这个名字找）。

C# 要求：

```csharp
using System.Runtime.InteropServices;

public class WebGLBridge : MonoBehaviour
{
    public static void NotifyReady() { /* ... */ }
    public static void NotifyPong(string message) { /* ... */ }

    // H5 → Unity
    public void Ping(string message) { /* 记录并 NotifyPong(message) */ }
}
```

条件编译：

```csharp
#if UNITY_WEBGL && !UNITY_EDITOR
    [DllImport("__Internal")] private static extern void JsNotifyReady();
    [DllImport("__Internal")] private static extern void JsNotifyPong(string message);
#else
    private static void JsNotifyReady() => Debug.Log("[Bridge] ready");
    private static void JsNotifyPong(string m) => Debug.Log($"[Bridge] pong: {m}");
#endif
```

`.jslib` 要求：

```javascript
mergeInto(LibraryManager.library, {
  JsNotifyReady: function () {
    try {
      if (window.SurvivalGameBridge && window.SurvivalGameBridge.onReady) {
        window.SurvivalGameBridge.onReady();
      }
    } catch (e) { console.error('[Bridge] onReady failed', e); }
  },
  JsNotifyPong: function (ptr) {
    try {
      var msg = UTF8ToString(ptr);
      if (window.SurvivalGameBridge && window.SurvivalGameBridge.onPong) {
        window.SurvivalGameBridge.onPong(msg);
      }
    } catch (e) { console.error('[Bridge] onPong failed', e); }
  }
});
```

要点：
- `.jslib` 放在 `Assets/Scripts/Bridge/` 下即可，Unity 会自动识别
- C# 字符串参数到 JS 侧是 UTF8 指针，必须 `UTF8ToString(ptr)`
- 所有 JS 调用包 `try/catch`，JS 异常不能拖垮 Unity

## 5. `Assets/Editor/BuildScript.cs`

菜单项：`Survival/Build WebGL`
静态方法：`BuildWebGL()`（供 batchmode 调用）

步骤：

1. 确保 `Assets/Scenes/Game.unity` 在 `EditorBuildSettings.scenes` 中
2. 设置：
   - `PlayerSettings.companyName = "Demo"`
   - `PlayerSettings.productName = "SurvivalGame"`
   - `PlayerSettings.bundleVersion = "0.1.0"`
   - `PlayerSettings.colorSpace = ColorSpace.Gamma`
   - `PlayerSettings.WebGL.compressionFormat = WebGLCompressionFormat.Brotli`
   - `PlayerSettings.WebGL.decompressionFallback = true`
3. **清空** `web/unity/`（保留该目录本身）
4. `BuildPipeline.BuildPlayer` 输出到 `web/unity`
5. 失败：`Debug.LogError` + `EditorApplication.Exit(1)`；成功：`EditorApplication.Exit(0)`
6. 无论成功失败，日志都要能落盘

### 构建后必须生成 `web/unity/build-info.json`

不同 Unity 版本的产物文件名不同（`.loader.js` / `.framework.js` / `.data.br` / `.wasm.br` 等），**必须扫描实际产物生成，不能硬编码**：

```json
{
  "loaderUrl": "Build/xxx.loader.js",
  "dataUrl": "Build/xxx.data",
  "frameworkUrl": "Build/xxx.framework.js",
  "codeUrl": "Build/xxx.wasm",
  "streamingAssetsUrl": "StreamingAssets",
  "companyName": "Demo",
  "productName": "SurvivalGame",
  "productVersion": "0.1.0",
  "unityVersion": "6000.3.22f1",
  "builtAt": "2026-10-29T00:00:00Z"
}
```

扫描规则（相对 `web/unity/`）：
- loader：`*.loader.js`
- data：文件名包含 `.data`
- framework：文件名包含 `.framework.js`
- wasm：文件名包含 `.wasm`
- 路径统一用 `/`

## 6. H5 外壳（M0 最小版）

### `web/index.html`
- 容器 `max-width: 960px`，游戏区 `aspect-ratio: 16/9`
- `<canvas id="unity-canvas">`
- 覆盖层：`Loading...` / `Unity Ready` / 错误提示
- 一个按钮 `测试通信`，初始禁用
- 一个 `<p id="bridge-log">` 显示 pong
- 页脚显示版本号

### `web/js/bridge.js`

**必须在加载 Unity 之前**定义：

```javascript
window.SurvivalGameBridge = {
  onReady: () => {},
  onPong: (msg) => {},
};
```

流程：
1. `fetch('unity/build-info.json')`
2. 动态插入 `<script src="unity/<loaderUrl>">`
3. `createUnityInstance(canvas, config, onProgress)`
4. config 的 `dataUrl` / `frameworkUrl` / `codeUrl` 前面都加 `unity/`
5. 把 `unityInstance` 暴露给 `app.js`

错误处理：fetch 失败、loader 404、`createUnityInstance` 抛异常，都要在页面上显示错误文案，不能白屏。

### `web/js/app.js`
- `onReady` → 覆盖层显示 `Unity Ready`，启用按钮
- 按钮点击 → `instance.SendMessage('WebGLBridge', 'Ping', 'hello-from-h5')`
- `onPong` → 写入 `#bridge-log`

### `web/css/style.css`
移动优先；`100dvh`；`env(safe-area-inset-*)`；按钮最小 44px。M0 不追求好看。

## 常见坑（先看这里，别乱改配置）
- `SendMessage` 找不到目标：GameObject 名字必须是 `WebGLBridge` 且处于激活状态
- 页面白屏：先看 `fetch build-info.json` 是否 404，再看 loader 的文件名是否拼错
- 构建产物和 `build-info.json` 对不上：重跑构建，不要手改 json
- 中文字符串进 Unity 显示成方块：M0 的 UI 必须是英文
- batchmode 构建失败 "project is already open"：关掉 Unity 编辑器再构建
