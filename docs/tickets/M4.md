## 1. P0：手机能玩 + UI 去重（交付硬要求）

### 1.1 触控移动

- 全屏拖动，不做虚拟摇杆（规范 5.5 / 决策）。
- **输入抽象（已定，照这个改）**：
  - `PlayerInputSource`：抽象 MonoBehaviour，`public abstract Vector2 Move { get; }`
  - `KeyboardInput`：原 `PlayerInputController` 改名，WASD/方向键行为不变
  - `TouchInput`：触控 + 鼠标左键拖动
  - `PlayerInputRouter : PlayerInputSource`：持有两者，触控有输入就用触控，否则键盘
  - `PlayerController._input` 类型改为 `PlayerInputSource`；`SceneSetup` 挂 `PlayerInputRouter` 并注入两个子源
  - 平台判断只允许出现在 `PlayerInputRouter`；`PlayerController` 不判平台
- **现状偏差（2026-10-31）**：已落地的 `TouchInput` 是「每帧位移归一化、手停人停」。理论上连续移动要一直搓屏幕，
  但浏览器 CDP 拖动已通过，**真机手感未验**。先让用户在真机试 1 分钟：如果觉得需要反复抬手重拖，再改锚点相对；
  不要因为理论直接推翻已测通过的实现。Brotato 手机版用的是浮动摇杆，锚点相对与它一致，作为备选方案保留。
- **触控语义（已定）：锚点相对拖动**
  - 手指按下时把按点当虚拟摇杆中心（不画出来）：`Move = clamp((current - anchor) / maxRadius, 1)`
  - `maxRadius ≈ 0.2 × Screen.height`（设备像素，初始夹在 80～160）；死区 ≈ 8px；松手归零
  - 记录 `fingerId`；换手指（原手指抬起、touch 0 变成另一根）必须重新锚定，不能跳方向
  - 只跟踪第一根手指；鼠标按住左键拖动走同一逻辑（Editor 自测、桌面触屏）
  - 不采用「每帧 delta 归一化」：慢速拖动时方向会断断续续，手感差。真机只调 `maxRadius` / 死区
- H5：`#unity-canvas { touch-action: none; }`（现在 CSS 只有 `.btn { touch-action: manipulation }`），防拖动时页面滚动/缩放。
- 开始按钮点击后调用 `canvas.focus()`；Unity 6 从 document 收键盘，但焦点仍要正确。
- 暂停按钮：Unity HUD 的「暂停」在触屏下可点；确认 uGUI 触摸点击正常（单击即触发，不需要长按）。
- 验收：iPhone Safari 15+ / Android Chrome 真机，拖动四向跟手，不滚动页面，不出界；Ready/Paused/Won/Lost 下拖动无效。

### 1.2 手机 HUD 可读

- 现状：390×844 竖屏游戏区仅约 219px 高，`生命/时间/分数` 缩到几乎看不清（1280×720 参考 → 约 0.3 倍）。
- **方案（已定）：整块 Canvas 切换 `referenceResolution`，面板一起放大。**
  - 手机上面板按钮同样会小到点不准，只缩 HUD 不够用；桌面保持 1280×720 不变。
  - 新增 `HudCanvasScaler` 挂 Canvas：`Screen.width < 1000`（设备像素）→ `640×360`，否则 `1280×720`；
    分辨率变化（浏览器缩放/旋转）时重算；阈值和参考值设为常量，附 why 注释。
  - 预期：390 宽手机上 HUD 24pt ≈ 14 CSS px、按钮高 56 ≈ 34 CSS px；桌面无变化。
  - **实测（2026-10-31）**：当前 `HudLayout` 用 `rect.rect.width < 640` 在 390×844 上**确实切到了 640×360**
    （`docs/evidence/e2e-local-chrome-mobile-playing.png` 里 HUD 明显放大），所以先保留，不要按理论改。
    真机/换 Unity 版本时若发现不触发，再改用 `Screen.width`（设备像素）判断——以截图证据为准。
- 竖屏提示「横屏体验更佳」放 **H5 DOM**（`@media (orientation: portrait) and (max-width: 768px)`），不塞进 Unity（不重烤字体）。
- 安全区：canvas 已在 H5 的 `env(safe-area-inset-*)` padding 内，只做确认，不改 Unity。
- DPR：程序实测 Unity 6 的 loader **不读** `config.devicePixelRatio`（loader 里没有这个字段），
  所以这条改成「真机验证」：先看 390 宽截图的清晰度与帧率；确实糊再查 Unity 6 的 canvas/`Module` 方案，
  不要为了 DPR 改 loader。Android 中端若 <30 FPS，优先降分辨率/关 AA。
- 验收：390×844 + 844×390 截图，中文清晰、不重叠、不溢出；旋转后重算正确。

## 2. P1：大地图 + 敌人手感 + 素材

> 详细参数/验收见 `docs/玩法增强.md`；严格按顺序，每步单独构建/验收。**M4-B 不碰 H5。**

### 2.0 大地图 + 相机跟随（B0，先做）

目标：地图 36×20（约 2×2 屏），相机跟随玩家并钳制在地图内；**玩家活动范围 = 地图，不再 = 视野**。

- `GameConfig` 增加 `MapWidth = 36`、`MapHeight = 20`；玩家边界 = 地图边界 − 玩家半径/精灵半宽。
- 新增 `CameraFollow`（场景组件，SceneSetup 生成）：
  - `LateUpdate` 跟随玩家；指数平滑 `t = 1 - exp(-k*dt)`，k≈8；不要用 `Lerp(a, b, 0.1f)`（帧率相关）。
  - 相机半宽/半高 = `orthographicSize × aspect` / `orthographicSize`；x/y 各自 clamp 到
    `±(MapWidth/2 - halfW)`、`±(MapHeight/2 - halfH)`。
  - 地图边缘处相机停住、玩家仍可见；重开时玩家回原点，距离 >8 直接 snap，避免长距离回拉。
- `PlayerController.RefreshBounds` 改为按地图边界算，不再用 `camera.ViewportToWorldPoint`；相机移动不影响玩家边界。
- 背景：`CreateBackground` 的 tiled size 改成地图大小（36×20），让地图边缘可见（外面是相机 clear color），
  **不能有看不见的空气墙**；可加 0.2 单位描边（可选）。
- `EnemySpawner.GetSpawnPosition`：
  - 以**玩家**为中心、半径约 `1.15 × 相机半对角线`（≈11.7）随机取点；
  - **拒绝落在相机视野内（margin 0.05）的点**，最多重试 8 次；全失败则退回视野外最远方向；
  - 不能只按相机视口 ±0.15：相机跟随有滞后，地图边缘会"脸上刷怪"；出生点可以在地图外（虚空），走进来即可。
- `EnemyAI` 回收改为「离开相机视野（viewport ±0.05）持续 3 秒」→ `Recycle`；删除 25 单位阈值。
- 验收：
  - 玩家能从地图中心走到四边，相机平滑跟随、玩家始终在画面内，地图边缘有明显视觉边界。
  - 在地图边缘跑动/绕圈时不会在视野内贴脸刷怪；身后离屏 3 秒的敌人被回收，新敌人从视野外补进。
  - 站着不动时 20 只上限仍有效；重开后玩家、敌人、相机全部回初始状态。
  - 60 FPS 桌面；`Update` 无每帧分配；相机移动不引起 UI 抖动。

### 2.1 `EnemyDefinition`（已落地，保留）

- 资产 `Assets/Configs/def_Enemy_Chaser.asset`，由 `SceneSetup.EnsureEnemyDefinition()` 创建；
  字段：`sprite / moveSpeed / contactDamage / colliderRadius`。首次构建时生成，**必须入库**。
- `NewScene` 之后重新 `LoadAssetAtPath` 再注入（遗留问题 3 的坑）。
- **不新增 `ArtConfig`**：玩家/背景/UI 的 sprite 仍由 SceneSetup 常量路径取，换图覆盖同名 PNG 即可。

### 2.2 拥挤抖动修复（B1 第一项，必做）

现状 `EnemyAI`：`push += offset / sqrDistance` 再 `seek + push × 1.5` 归一化，密集时方向每帧翻转；
`StanceOffset × StanceWeight = 0.18`，所有敌人实际仍挤在玩家中心。详见 `docs/玩法增强.md` 2.1。

**改法**：

- `EnemyAI` 只做 seek + 站位角，不再把 separation 加进方向。
- `EnemySpawner` 每帧 1～2 轮两两位置修正：`minDist = 0.9～1.0`，每对各推开一半；O(n²)、无分配。
- 停距 `playerRadius + enemyRadius - 0.08`（约 0.7）+ 8～12 个站位角，接触伤害仍由 Trigger 触发。
- 可选攻击名额：最多 6 只在伤害环内，其余在 1.2～1.5 环等待。
- 不推荐改动态 Rigidbody；若保留 steering 分离，改线性衰减 `(1-d/r)`、权重 0.6～0.8、最近 4～6 个邻居、速度平滑。

**验收**：20 只围住玩家时不持续抖动、不长期重叠；站位环成立；玩家仍能移动/掉血；`Update` 无分配。

### 2.3 速度扰动 + 压力曲线

- 每只实例存基础速度 `_speed = definition.moveSpeed × Random.Range(0.88f, 1.12f)`，夹到 ≤2.2（玩家 3.2）。
- **压力曲线**：`EnemyAI.Update` 里再乘 `Mathf.Lerp(1f, 1.15f, spawner.RoundElapsed / RoundDuration)`，
  **作用于已存在敌人**（27 秒后没有新敌人，生成时算死的系数会失效）；最终仍 ≤2.2。
- 可选：30 秒"涌潮"一次补 3～4 只，只在实测后半局太平淡时加；不新增中文 UI 文案。

### 2.4 视野外回收

- 条件：离开相机视野（viewport ±0.05）持续 `EnemyRecycleSeconds = 3` → `Unregister` + `Destroy`。
- 刚出生的敌人从视野外进入约 0.8～1.5 秒，3 秒计时不会误杀；回收只发生在玩家看不见的地方。
- 重开后列表清零；`ClearEnemies` 之外不残留 null。

### 2.5 素材

- 轻像素风（Kenney CC0 等），下载走 7897 代理，保留 LICENSE 放 `Assets/Sprites/third-party/`。
- 直接覆盖 `Assets/Sprites/spr_player.png` / `spr_enemy.png` / `spr_background_grid.png`
  （`EnsureSprite` 只在文件缺失时写占位，**不会覆盖已有文件**）。
- **替换后必须重设导入设置**：PPU 32、Filter Point、Compression None、背景 Repeat、Single sprite；
  把 `ConfigureSpriteImporter` 改成对已存在文件也执行（或用菜单重新导入），不要手点。
- 替换后确认碰撞半径与视觉尺寸匹配；需要时改 `EnemyDefinition.colliderRadius`。
- 时间盒半天，不做动画；素材不计入包体预算。

### 2.6 可读性 / 变体（可选，Brotato 借鉴）

- 同一定义生成时加 ±5% 缩放/轻微色调，20 只不糊成一坨；出生可做 0.2 秒淡入（可选）。
- 最多 1 个变体：**快速变体**（速度 2.2、碰撞 0.32、伤害 10、偏暖色）或**近战变体**（`玩法增强.md` 第 4 节），二选一；
  只有 B0/B1 全绿且时间充足才做。
- 不借 Brotato 的自动攻击/武器/道具/商店/Boss——不在作业要求内。

验收：

- B0：地图/相机/边缘/视野外生成与回收全部通过。
- 20 只不同时重叠；玩家跑动后能继续生成；重开清空。
- 敌群从多方向逼近；30～60 秒压力明显上升，但玩家仍能靠走位拉开。
- **5 局人工**：胜率 40%～80%，首次受击 10～30 秒（数据写进 `docs/M4-执行记录.md`）。
- 60 FPS 桌面 / ≥30 FPS 中端手机；`Update` 无每帧 GC。
- 包体增长 ≤0.5MB（不含素材）。
