## 1. P0：手机能玩 + UI 去重（交付硬要求）

### 1.1 触控移动

- 全屏拖动，不做虚拟摇杆（规范 5.5 / 决策）。
- 输入抽象（最小版）：
  - `PlayerInputSource` 抽象 MonoBehaviour，暴露 `Vector2 Move`
  - `KeyboardInput`：WASD/方向键
  - `TouchInput`：`Input.touchCount` / `Input.GetTouch(0)`，拖动方向；同时兼容鼠标拖动（Editor 自测）
  - `PlayerController` 只依赖基类
- SceneSetup 同时挂 Keyboard + Touch，或由一个组件选择；不要在 `PlayerController` 里写平台判断。
- H5：`#unity-canvas { touch-action: none; }`，防止拖动时页面滚动/缩放。
- 开始按钮点击后调用 `canvas.focus()`；Unity 6 从 document 收键盘，但焦点仍要正确。
- 暂停按钮：Unity HUD 的「暂停」在触屏下可点；确认 uGUI 触摸点击正常。
- 验收：iPhone Safari 15+ / Android Chrome 真机，拖动四向跟手，不滚动页面，不出界。

### 1.2 手机 HUD 可读

- 现状：390×844 竖屏游戏区仅约 219px 高，`生命/时间/分数` 缩到几乎看不清。
- 方案（二选一，按实测）：
  - 手机端切换 `CanvasScaler.referenceResolution`（如 640×360）或 `scaleFactor` 下限，让 HUD 字号等效放大；
  - 或按屏幕宽度给 HUD 单独缩放（只缩 HUD，不缩面板文字）。
- 竖屏提示「横屏体验更佳」；横屏 844×390 实测 HUD 可读。
- 安全区：H5 已用 `env(safe-area-inset-*)`；Unity HUD 在 canvas 内，检查不被刘海遮挡。
- DPR 限制 1.5～2；记录 iPhone/Android 帧率。
- 验收：390×844 + 844×390 截图，中文清晰、不重叠、不溢出。

### 1.3 结算 UI 只保留一套

- 现状：Unity 画布内「失败/得分/重新开始」+ H5 下方「失败/本次得分/最高分/重新开始」重复。
- 方案：**H5 嵌入模式下隐藏 Unity ResultPanel**，由 H5 统一展示成绩与重开；Editor 保留 Unity 面板自测。
  - `WebGLBridge.StartGame` 时置 `EmbeddedMode = true`（或 H5 发 `SetEmbedded(true)`）
  - `ResultPanel.HandleStateChanged`：`show = (Won/Lost) && !embedded`
  - PausePanel 保留（Unity 内继续按钮仍可用）
- Unity 明细「存活 150」改为「存活分 150」，避免和 H5 的「存活 15.7 秒」混淆。
- 验收：结算时画布内无第二套面板；H5 卡片完整；Editor 仍能看到 Unity 面板。

### 1.4 操作提示

- H5 开始区下方：
  - 桌面：`操作：WASD / 方向键移动 · 躲开敌人 · 存活 60 秒`
  - 手机（触控完成后）：`操作：拖动屏幕移动 · 躲开敌人 · 存活 60 秒`
- 按 `pointer: coarse` 或宽度切换；不要在触控未实现时对手机写「拖动」。
- 结算卡片可重复一行操作提示。
- 用 DOM 文本，不要塞进 Unity HUD（避免字体图集重烤）。

### 1.5 切窗 / 暂停体验（M3 线上反馈，M4 P0）

- `window.blur` / `focus` → 发 `SetPausedByVisibility`；失焦自动暂停并弹暂停面板，切回**不瞬时恢复**
  （先停住，避免切回来就被围死）。
- PausePanel 加 3-2-1 倒计时（`Time.unscaledDeltaTime`，暂停时 `timeScale=0` 也要走），倒计时结束才 `Resume`。
- H5 在 Playing 状态显示「游戏中」，并说明「暂停按钮在游戏内」——现在开始按钮消失后页面没有任何状态提示，像卡死。
- 测试：**打部署后的线上 URL**，用**真实 Alt-Tab**失焦/切回，禁止再用 `document.hidden` 模拟；
  每个状态（Playing / 失焦暂停 / 倒计时 / 恢复）截图进 `docs/evidence/m4-*.png`。

### 1.6 加载性能（M4 评估，M5 前决策）

- 现状：WebGL 产物约 9.4MB（wasm 6.96MB + data 2.45MB + framework/loader），Netlify 实测约 165KB/s，
  首次加载 50～61s（含代理）。
- M4 优先评估**国内托管**；M4/M5 评估 stripping / 缓存策略（Brotli、CDN、分片预加载）。

## 2. P1：敌人手感 + 正式素材

> 详细参数/验收见 `docs/玩法增强.md`；严格按顺序，每步单独构建/验收。

1. **`EnemyDefinition` 接缝**：先只放 1 个基础追击定义；`GameConfig` 继续管全局生成参数。
2. **软分离**：O(n²)，20 只上限；`ActiveEnemies` 只读列表；无分配。
3. **速度扰动**：±12%，上限 2.2（玩家 3.2）。
4. **远距离回收**：>1.5 屏且 3 秒 → 销毁 + `Unregister`，释放名额。
5. **包围站位**（可选）：生成角偏移，避免一条线。
6. **素材**：
   - 轻像素风（Kenney CC0 等）；`ArtConfig` / `EnemyDefinition` 解耦；PPU 32、Point、Compression None。
   - 玩家/敌人/背景/UI 九宫格；时间盒半天，不追求动画。
   - 替换后确认碰撞半径与视觉尺寸匹配；必要时改 `EnemyDefinition` 的碰撞半径。
7. **近战变体（P2，可选）**：只有前面全绿且 M5 时间充足才做；最多 1 种，按 `玩法增强.md` 第 4 节。

验收：

- 20 只不同时重叠；放风筝后能继续生成；重开清空。
- 敌群从多方向逼近，不再一条线。
- 60 FPS 桌面 / ≥30 FPS 中端手机；`Update` 无每帧 GC。
- 包体增长 ≤0.5MB（不含新素材）。
