## 背景

作业要求 H5 有"昵称 + 开始游戏按钮"，所以 H5 的开始按钮**不能删**；同类作品通常在这之后还有一层
Unity 主菜单（难度/继续/开始）和暂停菜单。本项目目前是"H5 开始 → Unity 直接 Playing"，缺这一层。

## 1. P0（必做）：H5 全屏按钮

- 位置：H5 游戏区右上/标题旁；"全屏" / "退出全屏"。
- 实现：`gameFrame.requestFullscreen()`（或 `document.documentElement`）；`fullscreenchange` 更新按钮文案。
- 全屏时：隐藏标题/页脚/操作提示/竖屏提示，画布按 16:9 letterbox，背景纯色；HUD 由 `HudCanvasScaler` 重算。
- iOS Safari 对任意元素全屏支持有限：`requestFullscreen` 失败时捕获并提示
  "当前浏览器不支持网页全屏，请横屏或添加到主屏幕"；不要卡在按钮无响应。
- 冲突：`Esc` 在浏览器全屏里通常用于退出全屏，所以暂停快捷键必须有 `P`（见 M4 §1.7）。
- 验收：
  - 桌面 Chrome/Edge、Android Chrome 可进/出全屏，按钮文案随 `fullscreenchange` 更新；
  - 全屏后隐藏页头/页脚/操作提示/竖屏提示，画布 16:9 letterbox，背景纯色；
  - 全屏下触控拖动、暂停（面板/P）、结算、重开正常；
  - iPhone Safari 不支持时捕获错误并提示「当前浏览器不支持网页全屏，请横屏或添加到主屏幕」，按钮不能无响应；
  - 可选 best-effort：`screen.orientation.lock('landscape')`，失败就保留「横屏体验更佳」提示；
  - **重跑响应式矩阵**：全屏/退出全屏两种状态各截 390×844、844×390、1280×720；
  - console 0 error。

## 2. P0：暂停菜单（小，建议做）

现在 PausePanel 只有"继续"。补成：

- 继续（**点后 3-2-1，再恢复**；失焦暂停切回后也停在这里，等玩家主动继续）
- 重新开始（`RestartGame`，需要确认不误点；先按 M4.6 P1 落，不依赖 Menu 状态）
- 注意：3-2-1 按 M4.6 保留，但**只由玩家点继续/按 P 触发**；不要恢复成失焦自动倒数
- 返回主菜单（进入 Unity 主菜单；局内状态是否保留见 §3）
- 退出到网页（可选；Unity 发一个 `onExitToShell` 事件，H5 回到开始界面；不刷新页面）

不新增中文以外的东西；暂停菜单的文案走 `UiStrings`，新增字要同步字体子集。

## 3. P1：Unity 主菜单 + 难度（中，1～2 天）

- 入口流程：H5 昵称 +「开始游戏」→ Unity `Menu`（不是直接 Playing）→ 选择难度 → 开始 → Playing。
- **状态机**：新增 `GameState.Menu`（或明确复用 `Ready` 并加 `menu` 标记）。
  推荐新增 `Menu`，避免"Ready 既是等待又是菜单"的歧义；`onStateChange` 要能表达 Menu。
- **协议**：`StartGame` 语义从"Ready→Playing"改为"Ready→Menu"；新增 `ReturnToMenu`（或复用 `RestartGame` + 菜单标记）；
  协议版本升到 **2**，`docs/bridge-protocol.md` 同步；H5 的页面状态机要处理 Menu（隐藏开始按钮/显示"请在游戏内选择"）。
- **难度**：3 档（简单/普通/困难），只改敌人参数（速度/上限/生成间隔/伤害）与压力曲线，不新增敌人类型；
  参数进 `GameConfig` 或 `DifficultyProfile`，菜单选择只影响本局；不做排行榜分档。
- **继续**：局内返回主菜单时保留当前回合状态（暂停冻结），"继续"恢复；**不跨刷新持久化**。
- 验收：H5 开始 → 菜单 → 三档难度可玩 → 暂停 → 返回菜单 → 继续/重开；H5 与 Unity 状态不打架；
  协议文档、`acceptance.md`、E2E 同步；难度数据记录（5 局）。

## 4. P2：保存并退出 / 跨刷新继续（不建议本次做）

60 秒单局，持久化需要序列化敌人位置、计时、随机种子、生成器状态、分数；成本大、收益低。
建议只做"暂停 → 退出到菜单/网页"，刷新后重开。若用户坚持，单独立项，不挤 M5。

## 5. 排期与边界

| 项 | 建议 |
|---|---|
| H5 全屏 | M4-B1，与键盘暂停同批 |
| 暂停菜单 | M4-B1，全屏之后 |
| Unity 主菜单 + 难度 | M4.5，M5 前由用户决定；做不完就停在当前可玩状态 |
| 持久存档 | 不做 |

**硬边界**：M5 的 17 条验收、真机、构建/托管优先；主菜单/难度不能拖过交付线。

1. 先做 M4 §1.7 键盘暂停（Esc/P）——和全屏冲突相关。
2. 再做本 ticket §1 全屏；§2 暂停菜单。
3. §3 主菜单/难度另起一个 change，先改协议/状态机文档，再写代码；不要和 M4-B1 混一起。
