# 测试计划（M3 后补齐）

> 原则：**先保证"可重复"，再追求"覆盖多"**。手工截图只能证明"跑过一次"，不能防回归。
> 本文件是 M4/M5 的测试门槛；不要求 100% 单测覆盖。
> 前置：当前实现事实见 `docs/实现总览.md`；文档权威顺序见 `docs/文档地图.md`。

## 1. 分层

| 层 | 做什么 | 工具 | 频率 |
|---|---|---|---|
| 单元 | 纯逻辑：`ScoreService` 计分/重置/胜利奖励 | Unity EditMode（可选，需 asmdef） | 改计分时 |
| 集成 | 状态机、重开、Ready 冻结、可见性暂停 | Unity PlayMode / Editor 脚本 | 每个里程碑 |
| E2E | 加载→昵称→开始→结算→最高分→刷新 | Playwright（`tools/e2e/`，不随 `web/` 发布） | M4/M5 每次构建 |
| 手动 | 真机、跨浏览器、手感、性能 | 人 | 每个里程碑 |

不做的：UI/MonoBehaviour 全量单测、CI 跑 Unity 构建、为覆盖率而覆盖率。

## 4. E2E smoke 脚本（M4 实现）

位置：`tools/e2e/`（独立 `package.json`，不进入 `web/`；不引入 H5 构建链）。

步骤：

1. 起静态服务（`python -m http.server` 或 Node）
2. 打开页面，等待 `onReady`（开始按钮可用）
3. 填昵称，点开始，确认 H5 进入 Playing（开始按钮隐藏/昵称禁用）
4. 等待结算：优先用**仅开发构建**的快速局开关；没有就等一局
5. 断言：结果标题、本次得分、最高分、昵称、存活秒数
6. 刷新：断言最高分/昵称仍在
7. 连续重开 3 次：断言无重复结算、分数不累加
8. 截图 + console log 落到 `docs/evidence/e2e-*`
9. 任何 console error → 失败

快速局开关（可选）：`?test=1` 时 H5 发 `SetDebugRound(5)`，Unity 仅在 `UNITY_EDITOR || DEVELOPMENT_BUILD` 处理；正式构建忽略/不编译。不要把它带进线上。
