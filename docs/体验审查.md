# 体验审查（对照同类游戏，2026-10-31）

> 文档版本：2026-10-31T19:40+08 · 作者：策划 · 改前必须从磁盘重读；上下文旧副本作废。
> 目的：主动按同类产品的通行做法审当前构建，避免用户逐个报「正常玩都会注意到」的问题。
> 方法：Brotato / 20 Minutes Till Dawn / Vampire Survivors / 通用 Web-Unity 外壳对照 +
> 线上 §1.7 构建截图 + Honor 90 Pro 局域网真机试玩。证据见 `docs/evidence/`。

## 1. 结论摘要（先看这 5 条）

1. **暂停/恢复语义是反的**（P0）：失焦后自动 3-2-1 继续；手动继续却即时。网页游戏的通行模式是
   「失焦保持暂停、恢复必须用户触发」；本作再在**玩家点继续后**加 3-2-1（手机挪手时间）。→ `M4.6` §1。
2. **结算卡片首屏只露一半**（P0）：`scrollIntoView({block:'nearest'})` 滚不到位。→ `M4.6` §2。
3. **暂停面板只有「继续」**（P1）：同类暂停菜单至少「继续 / 重新开始」。→ `M4.6` §3，返回主菜单留 M4.5 §3。
4. **没有全屏入口**（P1）：手机浏览器地址栏占高度；同类 Web 游戏普遍有。→ `M4.5` §1（托管通了再做）。
5. **H5 版本串停在 `0.1.0-m4.4`**（P1）：部署后无法一眼确认线上是不是最新包。→ 每次发布递增，最终 `1.0.0`。

## 2. 发现清单

| # | 现象 | 同类做法 | 影响 | 处置 |
|---|---|---|---|---|
| F1 | 失焦 → 暂停 → 切回自动 3-2-1 → 自动继续 | 网页游戏：失焦保持暂停，点 Resume 才继续；本作在玩家点继续后**再倒数 3 秒**（手机挪手） | 玩家没准备好就被继续，可能立刻掉血；手动/自动行为不一致 | **M4.6 P0** |
| F2 | 结算卡片在首屏只露上半截（1280×720 实测） | 结算覆盖游戏区或完整滚入视野 | 「结束了却看不到分数/重开」 | **M4.6 P0** |
| F3 | 暂停面板只有「继续」 | 暂停菜单：继续 / 重新开始 / 设置 / 退出 | 想重开只能等死或刷新；不符合暂停菜单预期 | **M4.6 P1**（继续+重开）；返回主菜单 → M4.5 §3 |
| F4 | 无全屏按钮 | Web 游戏普遍有；移动端可隐藏地址栏 | 手机上游戏区被浏览器 chrome 压缩 | M4.5 §1（托管通过后，2 小时盒） |
| F5 | H5 版本串 `0.1.0-m4.4`，构建已到 §1.7 | 每次发布递增版本号 | 线上排查/验收易误判旧包 | M4.6/M5：发布时同步递增 |
| F6 | 20 只敌人视觉上仍轻微交叠（sprite 直径 1，中心距约 0.92） | 角色缩放/描边/色调区分 | 观感拥挤，但不影响判定 | M4.6 §4 可选：占位 sprite 缩到 0.85～0.9 |
| F7 | Playing 时页头仍显示昵称输入框（已禁用） | 游戏中收起页头，腾出空间 | 手机纵向空间浪费；视觉上像还能改 | 可选：Playing/Paused 收起页头；不阻塞 |
| F8 | 结算后只能「重新开始」同昵称；换昵称要刷新 | 返回开始页 / 换角色 | 作业未要求；刷新可接受 | M4.5 §2/§3（退出到网页/主菜单） |
| F9 | 开局瞬间显示「时间 00:60」，下一帧变 00:59 | 显示 01:00 或 60 | 轻微违和 | P2，顺手可改；不单独排期 |
| F10 | 竖屏游戏区仅约 220px 高 | 提示横屏 / 全屏 | 已有「横屏体验更佳」提示 | 保持；全屏做好后受益 |
| F11 | 无音效 | 同类有受击/胜负音效 | 作业未要求；WebGL 音频需用户手势解锁 | 不做（可选） |
| F12 | 结算时画布内 HUD 仍在（生命 0/100、分数） | 结算覆盖/冻结画面 | 信息重复但不误导 | 可接受，不改 |
| F13 | 开局没有准备倒计时 | Brotato 波次开始有短倒计时 | 点开始即开跑，手机端可能手忙脚乱 | 可选；本次不做，避免再加一套倒计时语义 |
| F14 | 失焦时按住的键/触摸可能残留（待验证） | WebGL 通用坑：keyup 在别的窗口丢失；触摸锚点残留 | 恢复后玩家可能持续移动 | M4.6 §1.3 先测；复现再加 `ResetState` |
| F15 | 长时间切后台后首帧 delta 尖峰 | 恢复时清帧时间基准/夹住 delta | 瞬移、计时跳变 | 已有 `maximumDeltaTime=0.1`；M4.6 用 30 秒切后台用例验收 |
| F16 | 回到页面没有“明确等你点一下”的覆盖层 | 网页游戏普遍显示 Resume 覆盖层（return state） | 玩家不知道游戏是否还在跑 | M4.6 F1：暂停面板就是这一层，切回保持显示 |
| F17 | 触控是隐形浮动摇杆，没有视觉反馈 | 同类手机游戏普遍显示摇杆圈/摇杆头 | 不知道中心与满速半径，速度变化无解释 | M4.7：加浮动摇杆可视化，**逻辑不变** |

## 3. 已经做对、不要回退的点

- 暂停按钮在游戏内右上角，触屏可点；Esc/P 桌面快捷键（全屏时 P 兜底）。
- 失焦/切后台自动暂停（不继续跑），H5 与 Unity 状态一致。
- 结算只保留 H5 一套；最高分 localStorage；刷新后仍在。
- 手机 HUD 放大（640×360 参考）、触控锚点相对拖动、页面不滚动。
- 大地图 + 相机跟随、视野外生成/回收、拥挤位置修正。
- 加载进度百分比、加载失败重试、文件协议提示。

## 4. 不做的项（明确边界）

- 自动攻击 / 武器 / 道具 / 商店 / Boss / 技能树 / 远程弹幕：不在作业要求内。
- 跨刷新持久化局内状态：60 秒单局，成本高收益低。
- 排行榜 / 账号 / 分享：作业未要求。
- 音效：可选，交付前不做（不挤占 M5）。

## 5. 维护方式

- 每个里程碑收口前跑一遍本清单；新发现的「正常玩就会注意到」的问题先记到这里，再决定是否进 ticket。
- 新玩法/新 UI/新入口流程：先更新 `docs/参考拆解.md`，再写实现；不要从需求原文直接跳到 UI。
