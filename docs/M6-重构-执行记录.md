## 1. 代码改动

**状态机**

- `Core/GameState.cs`：`Booting / Menu / Starting / Playing / Paused / Result`（`Starting` 为内部 3-2-1 过渡态）。
- `Core/GameManager.cs`：
  - `Menu → Starting → Playing`；`Paused → Starting`（继续/重开）、`Result → Starting`（再来一局）；
  - 3-2-1 由 GameManager 用 `unscaledDeltaTime` 持有（单帧夹 0.1s），`OnCountdownChanged` 只推整数；
  - 取消倒计时回来源态并复位 timeScale（Menu=1，Paused/Result=0）；
  - `LastRoundWon` 区分胜负；`StartGameImmediate` 仅供压测/自动化；
  - 暂停中「重新开始」与结算「再来一局」都走 3-2-1，倒计时结束才 `ResetRound`（取消可原样回结算）。
- `Core/PauseHotkey.cs`：Paused → `RequestResumeCountdown()`；Starting 忽略。
- `Core/ApplicationFocusPause.cs`（新）：失焦 Playing→Paused、Starting→取消倒计时；Editor 内跳过。
- `Core/PerfProbe.cs`：状态判断 `Menu`；autostart 改 `StartGameImmediate`（绕过 3-2-1）。
- `Core/GameConfig.cs`：新增 `GetProfile(Difficulty)` 供菜单倍率文案读取。

**UI（全部由 `SceneSetup` 代码生成）**

- `UI/MenuPanel.cs`（新）：三档难度卡 + 开始；选中紫底；菜单不显示最高分/昵称/全屏。
- `UI/StartCountdownPanel.cs`（新）：统一遮罩 + 大数字（菜单开始/继续/重开/再来一局共用）。
- `UI/PausePanel.cs`：继续 / 重新开始 / 返回菜单。
- `UI/ResultPanel.cs`：始终显示；胜利/失败 + 本局得分 + 难度/存活/倍率 + 再来一局/返回菜单；
  不显示昵称与分数明细（按 mock）；删除 `IsEmbedded` 抑制。
- `UI/HudView.cs`：Menu/Result 隐藏 HUD；暂停按钮仍只 Playing。
- `UI/UiStrings.cs`：新增菜单/暂停/结算文案（`生存挑战 / 存活 60 秒 / 简单… / 开始游戏 / 返回菜单 / 再来一局 /
  本局得分 / 难度 / 存活 / 秒 / 倍率 / × / ·`）。
- `Editor/SceneSetup.cs`：菜单/倒计时/暂停三按钮/结算两按钮；菜单倍率读资产；`Dim` 0.72。

**字体**

- `Assets/Fonts/ui-chars.txt`：75 字符（精简 ASCII + 58 汉字 + `×`/`·`）。
- `Assets/Fonts/NotoSansSC-UI-Subset.otf`：从完整 Noto Sans SC（OFL，仓库外）重裁，19KB / 75 glyph。
- `tools/font-subset.py`（新）：参数化重裁脚本；完整字体不入库。
- `Assets/Fonts/NotoSansSC-UI-SDF.asset`：构建前自动重烤（1024×1024，Sampling 64 / Padding 8，75 字符）。

**协议 v3**

- `Bridge/WebGLBridge.cs`：
  - `onReady`：`protocol=3` + `capabilities=["enterGame","stateChange","gameOver","difficultyChanged"]`；
  - `onStateChange`：单一 `MapToWire` → `menu / playing / paused / result`；`Starting` 不发；
  - `onGameOver`：字段沿用 v2，`protocol=3`，`difficulty` 为实际采用值；
  - `EnterGame`：解析昵称 + `lastDifficulty`（`Menu` 外忽略并 warning）；回填难度抑制回声；
  - `onDifficultyChanged`：菜单选择变化时发；
  - 旧 `StartGame` 当 `EnterGame`；旧 `Pause/Resume/Restart/ReturnToMenu` no-op（一次性 warning）；
  - 删除 `IsEmbedded`；`SetPausedByVisibility` 保留为失焦兜底（`Starting` 也取消倒计时）。
- `Bridge/WebGLBridge.jslib`：新增 `JsNotifyDifficultyChanged`（页面未注册时静默跳过）。
- `docs/bridge-protocol.md`：升 protocol 3，含状态表、难度偏好、过渡矩阵。

**构建/版本**

- `Editor/BuildScript.cs`：`BundleVersion = 1.2.0`。
- `web/index.html`：四处 `?v=1.2.0`（只改版本串；H5 行为本阶段不变）。

## 4. 决策 / 偏差（留痕）

1. **6 视口在 standalone 上约束成 16:9 画布**（测试 CSS）：交付的 H5 画布是 16:9，全窗口竖屏不是目标；
   首轮竖屏截图里 HUD 互相压住，不作为通过证据。测试脚本 `tools/e2e/standalone-common.mjs` 注入
   `width:min(100vw,177.78vh)` 并隐藏 Unity 模板 logo/footer，重拍后全部通过。
2. **结算卡不显示分数明细**（按 mock/策划裁决）；`ScoreService` 字段保留，H5 仍可收到 `breakdown`。
3. **Result 状态隐藏 HUD**：320 宽时大号时间/分数会压住「胜利」标题；HUD 在 Playing/Starting/Paused 保留。
4. **`Dim` 0.6 → 0.72**：冻结的敌人不再压在倒计时数字/结算信息行上（P3）。
5. **`EnterGame` 只在 Menu 接受**：局内/倒计时/结算收到旧页重复进入时忽略并 warning（与协议文档一致）。
6. **`PlayerPrefs` 未使用**：难度偏好在会话内记，跨刷新由 H5 代存（`lastDifficulty` / `onDifficultyChanged`）。
7. **40 只 alloc 41.4KB/s** 高于 M6 记录 26~35，但 FPS/p95 与基线一致；已记入 `docs/遗留问题.md`，
   未定位到分配源，不宣称零回归。
