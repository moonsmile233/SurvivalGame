# 重构方案：游戏优先，H5 只做外壳（v1.2）

> 文档版本：2026-11-01T22:20+08 · 作者：策划 · 状态：**方案待用户看 mock 确认，未写实现**
> 依据：用户 2026-11-01 明确——“网页游戏网页这部分只是展示，游戏内部应该有完整游戏逻辑；H5 只做简单数据展示，实现外部框架，游戏脱离 H5 也能正常游玩。”
> 前序：`docs/proposals/proposal-M6-步骤2-难度与协议v2.md`、`proposal-M6-步骤2-交互最终版.md`（本方案**取代**其中 H5 拥有难度/开局/暂停/结算的部分）。

## 0. 一句话

**Unity 是完整游戏：主菜单、难度、开局、暂停、重开、结算、全屏都在画布里；H5 只是身份 + 入口 + 数据展示的外壳。**
脱离 H5 直接打开 Unity 构建，也能完整玩一局。

## 1. 为什么要改

- 现在 H5 拥有难度选择、开始、暂停提示、分档最高分、开局倒计时、部分结算；Unity 只负责局内。
- 结果：一次页面 UI 改动牵动全屏/滚动/缓存；未开局的全屏因为菜单在网页上，必须保留网页按钮。
- 这不是作业要求：作业只要求 H5 有昵称、开始按钮、分数回传、最高分 localStorage、响应式；
  难度/开局/暂停/重开/结算都是我们自己加进 H5 的。
- 用户 2026-11-01 决定：**职责归位**。

## 2. 目标 / 非目标

**目标**
- Unity 拥有完整游戏逻辑和局内全部 UI/状态；构建可独立游玩。
- H5 只做：昵称、进入游戏、当前/最高分展示、localStorage、嵌入与响应式。
- 协议大幅缩小：H5 不再发局内指令。
- 全屏内部零网页 UI；未开局全屏也是 Unity 菜单。

**非目标**
- 不改玩法/数值/计分（沿用 M6 已验收口径）。
- 不做账号/云存档/排行榜。
- 不新增素材；中文 UI 仍用现有 TMP 子集字体（新增静态文案要重烤字体）。

## 3. 作业原文映射（H5 部分，逐字）

| 原文 | 本方案怎么满足 |
|---|---|
| 输入玩家昵称； | H5 壳输入；昵称只在 H5 展示/保存，不进 Unity UI（任意字符字体画不出） |
| 开始游戏按钮； | H5 壳的「开始游戏」= 进入 Unity 游戏（加载/切到画布）；作业不要求它直接开打 |
| 嵌入 Unity WebGL 游戏； | 画布嵌在 H5 壳里；Unity 构建也可独立打开 |
| 游戏结束后，Unity 把分数传给 H5； | `onGameOver` 回传 result/score/difficulty/survived |
| H5 显示本次成绩和历史最高分； | H5 数据面板常驻展示；分档最高分 localStorage |
| 最高分使用 localStorage 保存； | 沿用 `survival.bestScore.{easy,normal,hard}` |
| 页面适配电脑和手机宽度。 | 壳的布局响应式；画布 16:9；允许纵向滚动、无横向滚动 |

面试官若期待“点一次 H5 按钮直接开打”，会看到两次点击；README/验收说明写清
“H5 开始 = 进入游戏，难度/开局在游戏内菜单完成”。

## 4. 职责边界

| 层 | 负责 | 不负责 |
|---|---|---|
| **Unity（游戏本体）** | 主菜单、难度选择、开局倒计时、游戏、暂停/继续、重开、返回菜单、结算、全屏状态 | 昵称输入、最高分持久化、页面布局 |
| **H5（外壳）** | 昵称、进入游戏、当前/最高分展示、localStorage、嵌入、响应式 | 难度、开局、暂停、重开、返回、结算操作、全屏内部 UI |
| **协议** | H5→Unity：`EnterGame`（昵称可选，仅日志）；Unity→H5：`onReady`、`onGameOver`、可选 `onStateChange`/`onExitToShell` | 删除 `StartGame(difficulty)`、`PauseGame`、`ResumeGame`、`RestartGame`、`ReturnToMenu` |

## 5. H5 外壳

### 5.1 布局与按钮（用户 2026-11-01 确认）

- 布局按网页游戏常规：**宽屏左侧数据栏 + 右侧 16:9 画布；手机顶部数据栏 + 下方画布**；
  页面允许纵向滚动、无横向滚动。
- 数据面板**常驻**：**共享最高分（不区分难度）** + 最近一局（从 `onGameOver` 更新）。
  具体分数口径后续再定；迁移时把现有 `bestScore.{easy,normal,hard}` 取最大值写入单一最高分（细节待定）。
- 昵称：进入前可编辑；进入后只读；不进 Unity。
- **「开始游戏」与「全屏」是两个独立按钮**（不合并）：
  - 开始 = 发 `EnterGame`，画布进入 Unity 菜单；游戏内的开始/重开不在 H5。
  - 全屏 = 浏览器全屏（外壳隐藏、画布独占）；全屏内部不再有任何网页按钮，退出靠 Esc/浏览器手势。
- Unity 菜单**不显示最高分**（最高分归 H5）。

### 5.2 H5 状态

| 状态 | 谁驱动 | H5 显示 |
|---|---|---|
| Shell | H5 | 昵称、开始、最高分面板；画布可显示“游戏已就绪” |
| Entered | `EnterGame` 后 | 数据面板保留；开始隐藏；画布内是 Unity 菜单/游戏 |
| GameOver | `onGameOver` | 数据面板更新本次/最高分；Unity 画布内显示结算 |
| Exited | `onExitToShell`（可选） | 回到 Shell，开始按钮重新出现 |

H5 不再有 Ready/Playing/Paused/Result 的页面状态机；这些只用于数据面板文案。

## 6. Unity 游戏

- **默认进入 Menu 状态**（Standalone 可玩），不依赖 H5 消息。
- Menu：标题、三档难度卡、开始；可选全屏按钮。
- Playing：现有 HUD/暂停键；暂停面板 = 继续 / 重新开始 / 返回菜单。
- Won/Lost：结算面板 = 本局得分 / 难度 / 存活时间；按钮 = 再来一局（同档）/ 返回菜单。
- 返回菜单 = 回 Unity Menu；可选「退出到网页外壳」→ `onExitToShell`。
- 昵称不显示（字体原因）；结算卡不显示昵称。
- 最高分不在 Unity 持久化；H5 负责展示与存储。

## 7. 协议 v3

| 方向 | 消息 | 说明 |
|---|---|---|
| H5→Unity | `EnterGame` | 进入游戏（加载完成/点击开始）；可选昵称仅用于日志，不渲染 |
| Unity→H5 | `onReady` | protocol=3、版本、能力位 |
| Unity→H5 | `onGameOver` | result、score、difficulty、survivedSeconds（H5 存最高分） |
| Unity→H5 | `onStateChange`（可选） | menu/playing/paused/result，仅用于 H5 数据栏/文案 |
| 删除 | `StartGame(difficulty)`、`PauseGame`、`ResumeGame`、`RestartGame`、`ReturnToMenu` | 全部由 Unity 内部处理 |

不设 `onExitToShell`：H5 外壳在普通模式下一直围绕画布存在，数据面板常驻；全屏只是显示模式，
退出全屏由浏览器处理，不需要游戏通知外壳。

兼容：v2 旧 H5 + 新 Unity —— 新 Unity 默认 Menu，旧 H5 的 `StartGame` 可当作 `EnterGame` 处理；
新 H5 + 旧 Unity 不支持，H5 与 Unity 同版本部署。

## 8. 全屏（用户 2026-11-01 确认）

- **入口在 H5 外壳**：与「开始游戏」并列的独立「全屏」按钮（浏览器手势，可靠）。
- Unity v1.2 不内置全屏按钮；独立运行时可用浏览器全屏（F11/系统快捷键），后续需要再加 Unity 按钮。
- **全屏内部零网页按钮**；退出靠 Esc（电脑）/侧滑返回或系统手势（手机），**不提供网页退出按钮**。
- 未开局全屏：画布显示 Unity 菜单（H5 壳隐藏）；游戏中全屏：只有 Unity HUD/暂停面板。

## 9. 昵称与字体

- 昵称只在 H5 渲染；Unity 不显示任意昵称。
- Unity 菜单/结算的中文静态文案加入 `UiStrings`，构建时重烤 TMP 字体子集。
- 玩家名在 Unity 内如需展示，只能显示“玩家”或空。

## 10. 两次点击

- H5「开始游戏」（进入）→ Unity 菜单「开始」= 两次点击。
- 理由：难度/开局归 Unity；作业要求 H5 有开始按钮；保持游戏内部完整。
- 缓解：Unity 菜单默认选中上次难度、开始按钮做大；README 说明。

## 11. 验收

1. **Standalone**：直接打开 Unity 构建，不经过 H5，完整走完 Menu→难度→游戏→暂停→重开→结算→返回。
2. **H5 壳**：昵称/开始/最高分/localStorage/响应式；进入后无任何局内控件；结算后数据面板更新。
3. **协议**：H5 不再发任何局内指令；`EnterGame` + `onGameOver` 跑通；旧字段不依赖。
4. **全屏**：入口可用（Unity 或 H5 兜底）；全屏内 0 网页按钮；Esc/手势可退；未开局全屏为 Unity 菜单。
5. **作业**：H5 七条逐项通过；README 写清“开始=进入游戏，菜单在游戏内”。
6. **回归**：三档数值/计分不变；17 条、E2E、6 视口、真机。
7. **性能**：不劣于第 2 步基线（桌面 40 只 165 FPS/p95 7ms）。

## 12. 实施顺序（预计 2～3 天，1～2 次构建）

1. 方案 + 状态表 + 静态 mock（本文 + `mock-ups/refactor-game-first/`）；用户确认。
2. Unity：状态机 Menu/Playing/Paused/Result + 菜单/暂停/结算 UI + 难度迁移 + 全屏尝试；构建 #1。
3. 协议 v3 + H5 薄壳：昵称/进入/数据面板/localStorage；删除旧局内控件；静态文件，无构建。
4. Standalone 验收 + H5 联动 + 全屏/真机 + 17 条回归；构建 #2（如需修 Unity）。
5. 文档同步（实现总览/acceptance/README/bridge-protocol）+ v1.2 发布（等用户）。

## 13. 风险 / 停点

| 风险 | 处理 |
|---|---|
| Unity 全屏被浏览器手势拒绝 | 兜底 H5 一个入口按钮；全屏内部仍无网页 UI |
| Unity 中文菜单字体缺字 | 静态文案进 UiStrings + 重烤；昵称不进 Unity |
| 两次点击不符合面试官预期 | README/验收写清；菜单默认上次难度、开始做大 |
| 重构拖垮 M6 | 独立 v1.2 线；M6 暂停在干净检查点；随时可回 main=476bf3d1 |
| 协议改动导致旧页面/旧包不兼容 | H5+Unity 同版本部署；`?v=`/构建版本一致；旧 StartGame 当 EnterGame |
| 游戏内 UI 与 H5 数据重复 | H5 只展示数据/最高分；Unity 展示本局；明确各自职责 |

## 15. 用户已确认（2026-11-01）

1. 布局：按网页游戏常规——宽屏左侧数据栏 + 右侧画布；手机顶部数据栏 + 下方画布。
2. 最高分：**不同难度共用一个最高分**；具体分数口径后续再定（迁移取现有三档最大值）。
3. **开始与全屏是两个独立按钮**，不合并。

5. 不需要“退出到网页外壳”或全屏退出按钮：外壳在普通模式下常驻；全屏退出靠 Esc/浏览器手势。
